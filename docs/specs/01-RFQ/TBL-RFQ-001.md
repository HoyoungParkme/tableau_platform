# RFQ — 요구·인터뷰

## 1. 배경과 동기

현대글로비스가 현대차에서 받는 완성차 생산·판매·재고 데이터를 태블로 대시보드로 보고 있다. 발주자는 대시보드를 열었을 때 질문 없이 AI가 해석(글과 차트)을 붙여 주는 서비스를 원한다. 기존 제품(Nabi, 챗봇형 태블로 분석 플랫폼)을 기준선으로 삼되, 챗봇은 없애고 밀어주는 브리핑으로 바꾼다. 납품 형태는 폐쇄망이며 화면은 발주자의 기존 태블로 포털 VODA에 단독 주소로 이식한다. LLM은 사내 H-chat을 쓴다.

요구는 2026-09-08 접수 원문 6건과 11차에 걸친 발주자 확정 회신 24건으로 구성된다. 원본 원장은 저장소 `docs/glovis/01_rfq.md`이며 원 ID(GLV-RFQ-nnn, GLV-ANS-nnn)를 각 항목에 병기한다.

## 3. 요구 사항

### 3.1 접수 원문 (2026-09-08)

#### Q1 대시보드에서 인사이트를 얻고 싶다

대시보드를 보고 인사이트를 얻고 싶다. 제품의 목적이다. (원 ID: GLV-RFQ-001)

#### Q2 주 사용자는 현업 담당자

주된 사용자는 현업 담당자이다. 소비자는 비개발자다. (원 ID: GLV-RFQ-002)

#### Q3 태블로 화면 제작팀과 접점 없음

태블로 화면은 다른 팀에서 개발하며 우리와 접점이 없다. 제작자에게 화면 설명을 받을 수 없다. (원 ID: GLV-RFQ-003)

#### Q4 대시보드와 Agent 간극은 기존 과정으로, 화자는 개발자

대시보드와 Agent의 간극은 기존과 동일한 과정(적재, 분석 프로필, 시트매핑)으로 메꾼다. 단 메꾸는 화자가 현업에서 개발자로 바뀌었다. (원 ID: GLV-RFQ-004)

#### Q5 챗봇 기능 삭제

챗봇 기능은 삭제되었다. 이에 따른 부수 기능(대화형 질의응답)도 필요 없다. (원 ID: GLV-RFQ-005)

#### Q6 질문 없이 인사이트, 차트도 함께

대시보드를 열면 질문 없이 인사이트를 얻는다. 글로만 보여주는 것이 아니라 새로운 인사이트를 차트로도 그려야 한다. (원 ID: GLV-RFQ-006)

### 3.2 1차 확정 회신 (2026-09-08)

#### Q7 인사이트 생성 시점

스냅샷 시점에 사전 생성한다. 사용자가 원하면 새로고침 버튼으로 다시 생성한다. 여러 사용자 간 캐시 공유 정책은 도메인 모델 정의 단계에서 결정한다. (원 ID: GLV-ANS-001)

#### Q8 차트의 재료

사용자가 사전에 등록한 분석가이드, 핵심 지표와 판단 기준을 바탕으로 인사이트를 뽑고 차트와 함께 보여준다. 기술 세부는 도메인 설계에서 결정한다. (원 ID: GLV-ANS-002)

#### Q9 대시보드 간 교차분석 제외

교차분석은 필요 없다. 인사이트는 하나의 대시보드 안에서만 뽑는다. (원 ID: GLV-ANS-003)

#### Q10 폐쇄망 LLM은 H-chat

폐쇄망에서는 H-chat을 사용한다. (원 ID: GLV-ANS-004)

### 3.3 2차 확정 회신 (2026-09-08)

#### Q11 외부에서 개발 후 폐쇄망으로 이식

폐쇄망에서는 AI 보조 개발을 쓸 수 없으므로 외부에서 만들어 안으로 이식한다. (원 ID: GLV-ANS-005)

#### Q12 인증 방식은 변경 가능, 현장은 TSM 신뢰 인증

Keycloak과 HMG SSO 방식은 변경될 수 있다. 실제 현장은 태블로 서버(TSM)에 신뢰할 수 있는 인증(trusted authentication)으로 구성되어 있다. (원 ID: GLV-ANS-006)

#### Q13 행 수준 보안 제외

행 수준 보안(RLS)에 해당하는 대시보드가 없다. RLS 유지 요구를 제외한다. (원 ID: GLV-ANS-007)

#### Q14 배포 형상은 VODA 이식

인사이트 화면만 따로 분리해 현대글로비스의 기존 서비스 VODA에 이식한다. 화면 분리는 그쪽 프론트에서 하므로 우리는 VODA 서버와의 연동을 고려하지 않는다. (원 ID: GLV-ANS-008)

#### Q15 개인 위젯 홈과 QA 검색 제외

개인 위젯 홈은 제외한다. QA 검색도 삭제한다(챗봇이 없으므로). (원 ID: GLV-ANS-009)

#### Q16 컨텍스트 그래프는 축소 유지

그래프 DB(Neo4j)·순회·관계도 화면은 제거하고, 지표와 시트를 잇는 연결 정보(Postgres)만 유지한다. (원 ID: GLV-ANS-010)

### 3.4 3차 확정 회신 (2026-09-08)

#### Q17 보고서 기능 제외

보고서 기능은 제외한다. 현업 접점은 VODA 브리핑 하나로 모은다. (원 ID: GLV-ANS-011)

#### Q18 외부요인 기능 제거, 스냅샷·판정은 유지

외부요인 기능(바깥 사정 등록·수집·검수·지표 연결)을 제거한다. 지표 스냅샷과 변동 판정은 브리핑 재료로 유지한다. (원 ID: GLV-ANS-012)

#### Q19 브리핑 차트는 Chart.js

브리핑 차트는 Chart.js(react-chartjs-2)로 그린다. LLM은 차트 라이브러리 스펙을 직접 쓰지 않고 자체 페이로드 계약만 채우며, 렌더는 결정적 변환이 맡는다. 기존 vega-lite 방식은 LLM이 스펙을 직접 써서 깨지기 쉬웠다. (원 ID: GLV-ANS-013)

### 3.5 4차 확정 회신 (2026-09-08)

#### Q20 시트 의미는 기계 초안과 사람 검수

기계가 초안을 쓰고 사람이 검수해 확정한다(수정도 가능). "사람 것이 있으면 기계가 안 채운다"는 제약이 아니다. 시트 의미는 두 칸이 아니라 하나의 값이 상태(초안, 확정)를 거치는 것이다. (원 ID: GLV-ANS-014)

#### Q21 새로고침은 요청자 화면에만 반영

배치(스냅샷) 브리핑은 전원이 동일하게 공유한다. 특정 사용자가 새로고침하면 그 결과는 그 사용자 화면(메모리)에만 반영되고 공유판은 바뀌지 않는다. 다른 사용자 화면에 영향이 가면 안 된다. (원 ID: GLV-ANS-015)

### 3.6 5차·6차 확정 회신 (2026-09-08)

#### Q22 백엔드 패키지는 core/web/infra 3층

core(경계 5) / web(라우터·요청응답 형태) / infra(외부 어댑터) 3층으로 간다. 어댑터 층은 유지하되 infra로 개칭하고, 웹 계층을 도메인 밖으로 분리한다. 진입 면이 둘(브리핑 화면=서명 주소, 관리 웹=로그인)이라 인증 경계가 폴더에서 보여야 한다. (원 ID: GLV-ANS-016)

#### Q23 새로고침 결과는 비동기 폴링

새로고침은 접수(실행 ID)를 즉시 받고, 화면이 주기적으로 상태를 조회해 완료 시 결과를 받는다. 생성은 수십 초 걸릴 수 있고 화면은 VODA 안이라 긴 동기 대기는 끊길 위험이 있다. (원 ID: GLV-ANS-017)

### 3.7 7차·8차 확정 회신 (2026-09-08)

#### Q24 브리핑은 고정 구조와 자율 생성 두 페이지

LLM이 매번 다른 인사이트를 내면 너무 광범위해진다. 브리핑 페이지를 두 개 둔다. A안은 현업 인터뷰로 정한 트래킹 지표 기반 고정 구조(렌더 구조는 시스템이 짜고 LLM은 내용 JSON만 채움), B안은 자율 생성이다. 한 주소 안 탭 2개(A 기본), 배치 때 둘 다 생성한다. 트래킹 지표 선정은 현업 인터뷰 항목이다. PDF 저장도 추가한다. (원 ID: GLV-ANS-018)

#### Q25 PDF는 서버 생성

PDF 저장은 서버 생성으로 확정한다(품질 일관성 우선). 렌더 스택은 구현 단계에서 확정한다. (원 ID: GLV-ANS-019)

#### Q26 우리 서버도 TSM 신뢰 호스트로 등록, 브리핑 인증은 서명 주소

TSM에 이미 VODA 서버가 신뢰 호스트로 등록돼 있고, 우리 서버도 동일하게 등록한다. VODA 연동은 서버 간이 아니라 VODA 프론트의 특정 페이지에서 버튼으로 우리 인사이트 화면을 여는 방식이다. 브리핑 화면 인증은 대시보드 단위 서명 주소(쿼리 token)로 확정한다. 이 시점에 H-chat API 형태는 발주자가 예시 코드를 전달 예정이었고, JSON 응답 지원은 확인 전이었다. (원 ID: GLV-ANS-020)

### 3.8 9차 회신 (2026-09-08, 레퍼런스 코드 접수)

#### Q27 VODA 정체와 신뢰 인증 실규약, 식별자는 사번

VODA는 Dfocus가 제작·운영하는 태블로 포털이다(고객사별 브랜치 glovis/seegene). 신뢰 인증은 POST {내부주소}/trusted (form-urlencoded, username=사번, target_site), 응답 본문이 티켓(실패 시 "-1"), 임베드 URL은 {프록시주소}/trusted/{ticket}/... 형식이다. 전사 식별자는 사번(로그인·태블로·HR 동일 키)이다. VODA에 브리핑 버튼을 넣는 작업은 범위 밖이며 우리는 단독 주소 제공까지 맡는다. H-chat 회신 전까지 개발·테스트는 기존 OpenAI 계열로 진행한다. (원 ID: GLV-ANS-021)

### 3.9 10차·11차 회신 (2026-09-08, H-chat)

#### Q28 H-chat은 OpenAI 호환 게이트웨이

H-chat은 AzureOpenAI 기반의 OpenAI 호환 멀티모델 게이트웨이(Claude/OpenAI/Gemini)다. Chat Completions 경로는 `POST .../hchat-in/api/v3/openai/deployments/{model}/chat/completions`, 인증은 Authorization 헤더(Project 키면 `X-Project-Id` 추가)다. 모델은 gpt-5.5, gpt-5.6-luna/terra(컨텍스트 1,050,000 / 출력 128,000). 기존 OpenAI 계열 호출 방식을 그대로 쓰고 base URL·헤더·모델명만 설정으로 전환한다. "OpenAI API와 다를 수 있음" 경고가 있어 JSON 복구·강등 배선은 유지한다. (원 ID: GLV-ANS-022)

#### Q29 H-chat 실호출 검증 성공

사내망 PC에서 v3 엔드포인트에 gpt-5.6-luna 호출 결과 200, chat.completion 정상 생성. 확정 사실 세 가지. 인증은 Bearer 접두 없이 키 원문을 Authorization 헤더에 넣는다. 모델은 날짜 스냅샷으로 해석된다(gpt-5.6-luna-2026-07-09). Azure 콘텐츠 필터가 켜져 있다. 시험 중 키가 화면 캡처에 노출됐으므로 공유 전 재발급을 권고했다. (원 ID: GLV-ANS-023)

#### Q30 JSON 모드는 지원 가정으로 진행

JSON 모드(response_format)는 지원된다고 가정하고 진행한다. 어댑터는 json_object를 기본으로 켜되 미지원·형식 위반 시 기존 JSON 복구·강등 배선이 받는다. 실검증은 반입 체크리스트로 이월한다. 이로써 인터뷰성 미결 Q-001~Q-009는 전부 종결됐다. (원 ID: GLV-ANS-024)

## 5. 첫 프로젝트

브리핑 갈래(태블로 대시보드에 AI 해설을 붙이는 것)가 첫 범위다. 기존 문서 사슬 01~11이 이 갈래를 다룬다. 인텔리전스 갈래(완성차 실적 + 뉴스·블룸버그·Marklines 결합 리포트)는 발주자 자료(기본계획, 과업지시 초안)로 방향만 잡혀 있고 이 원장에는 아직 등재되지 않았다.

## 6. 미정

- [ ] 인텔리전스 갈래 요구를 발주자 원문(기본계획.pptx, 과업지시 초안.xlsx) 기준으로 이 원장에 등재한다

- [ ] 완성차 데이터 과거 2년치 초기 적재 가능 여부. 현재 3개월치뿐이라 전년동월 대비를 계산할 수 없다
- [ ] 판매 IF에 CBU/CKD 컬럼 추가 가능 여부
- [ ] 과거 적재가 안 될 경우 전년동월 대비를 당분간 전월 대비로 대체해도 되는지
- [ ] 블룸버그·뉴스 데이터의 라이선스 범위(재배포, AI 학습)
- [ ] Marklines 실데이터 인입 일정. 현재 2019년 China·Japan 샘플뿐
- [ ] 워치리스트 국가를 3개국에서 10개국으로 갱신할지(자사 DBA 질의, 회신 대기)
- [ ] 사내망에서 Claude Code용 H-chat 엔드포인트 사용이 실제 허용되는지. 사실이면 [[#Q11]] 전제가 완화된다
- [ ] 트래킹 지표 선정을 위한 현업 인터뷰 일정 ([[#Q24]])
- [ ] JSON 모드 실검증 (반입 체크리스트로 이월, [[#Q30]])
