# RFQ — 요구·인터뷰

## 1. 배경과 동기

현대글로비스는 현대차 CDO와 JDA(2026-07)를 맺고 완성차 생산·판매·재고 데이터를 자사 인프라로 받기 시작했다. 발주자의 기본계획은 과업 세 개로 구성된다. 과업 1은 데이터 연계·자산화, 과업 2는 VODA 대시보드 신규·개선, 과업 3은 AI 지능형 분석환경과 인텔리전스 서비스다.

2026-09-16 발주자 설명으로 이 원장이 다루는 것의 구조가 확정됐다([[#Q54]] [[#Q55]]). 세 층이다.

1. 태블로 대시보드 3본(생산·판매·재고). 참고자료 A를 참조해 Dfocus 태블로 팀이 기획·제안한다.
2. 대시보드마다 Nabi Agent가 AI 인사이트 리포트를 붙인다. 브리핑 갈래 원장(`docs/glovis/01_rfq.md`)과 그 설계 사슬(02~11)이 이 층을 담당한다.
3. 종합 인텔리전스 리포트 1본. 대시보드 3본의 인사이트를 하나로 엮고, 외부요인(뉴스·블룸버그)은 이 리포트에서만 결합한다. 개요 시트(C3~C12)는 이 리포트의 디자인 방향이며 카드 구성은 고정이 아니다([[#Q56]]).

이 원장은 3층을 주 대상으로 하되 2층과의 연결(대시보드 인사이트를 3층의 정형 입력으로 받는 것)을 포함한다. 2층 자체의 설계 결정(차트 라이브러리, 새로고침, 패키지 구조)은 브리핑 갈래 문서를 따른다.

발주자가 든 문제는 세 가지다. 완성차 데이터가 외부 플랫폼(데이터인사이드)에 종속돼 추가 분석이 안 됐고, 담당자별 수기 수집과 엑셀 기반 VODA 운영이 이어졌으며, 내부 데이터 자산(블룸버그, 뉴스 API)과 결합한 인사이트 도출이 불가능했다.

납품 환경은 폐쇄망이고 화면은 VODA에 단독 주소로 이식하며 LLM은 사내 H-chat이다. 이 환경 사실은 브리핑 갈래 원장에서 확정된 회신을 그대로 가져왔고 원 ID를 병기한다.

범위 밖인 것. 현업 PPT 보고양식 대시보드 4본(과업지시 G6)과 기존 대시보드 개선 3본(G7~G9), 기본계획 슬라이드 11의 자연어 차트·태블로 개발 대행 분석환경.

원본 자료는 구글 드라이브 `글로비스-TableauAI/데이터` 폴더에 있다(01 요구사항, 02 연계데이터, 03 외부데이터, 04 분석로직, 05 메일기록).

## 3. 요구 사항

### 3.1 환경 사실 (브리핑 갈래 원장에서 승계)

#### Q1 대시보드에서 인사이트를 얻고 싶다

대시보드를 보고 인사이트를 얻고 싶다. 제품의 목적이다. (원 ID: GLV-RFQ-001)

#### Q2 주 사용자는 현업 담당자

주된 사용자는 현업 담당자이다. 소비자는 비개발자다. (원 ID: GLV-RFQ-002)

#### Q6 질문 없이 인사이트, 차트도 함께

대시보드를 열면 질문 없이 인사이트를 얻는다. 글로만 보여주는 것이 아니라 새로운 인사이트를 차트로도 그려야 한다. (원 ID: GLV-RFQ-006)

#### Q10 폐쇄망 LLM은 H-chat

폐쇄망에서는 H-chat을 사용한다. (원 ID: GLV-ANS-004)

#### Q11 외부에서 개발 후 폐쇄망으로 이식

폐쇄망에서는 AI 보조 개발을 쓸 수 없으므로 외부에서 만들어 안으로 이식한다. (원 ID: GLV-ANS-005)

#### Q14 배포 형상은 VODA 이식

인사이트 화면만 따로 분리해 현대글로비스의 기존 서비스 VODA에 이식한다. 화면 분리는 그쪽 프론트에서 하므로 우리는 VODA 서버와의 연동을 고려하지 않는다. (원 ID: GLV-ANS-008)

#### Q27 VODA 정체와 신뢰 인증 실규약, 식별자는 사번

VODA는 Dfocus가 제작·운영하는 태블로 포털이다(고객사별 브랜치 glovis/seegene). 신뢰 인증은 POST {내부주소}/trusted (form-urlencoded, username=사번, target_site), 응답 본문이 티켓(실패 시 "-1"), 임베드 URL은 {프록시주소}/trusted/{ticket}/... 형식이다. 전사 식별자는 사번(로그인·태블로·HR 동일 키)이다. VODA에 버튼을 넣는 작업은 범위 밖이며 우리는 단독 주소 제공까지 맡는다. (원 ID: GLV-ANS-021)

#### Q28 H-chat은 OpenAI 호환 게이트웨이

H-chat은 AzureOpenAI 기반의 OpenAI 호환 멀티모델 게이트웨이(Claude/OpenAI/Gemini)다. Chat Completions 경로는 `POST .../hchat-in/api/v3/openai/deployments/{model}/chat/completions`, 인증은 Authorization 헤더(Project 키면 `X-Project-Id` 추가)다. 모델은 gpt-5.5, gpt-5.6-luna/terra(컨텍스트 1,050,000 / 출력 128,000). 기존 OpenAI 계열 호출 방식을 그대로 쓰고 base URL·헤더·모델명만 설정으로 전환한다. (원 ID: GLV-ANS-022)

#### Q29 H-chat 실호출 검증 성공

사내망 PC에서 v3 엔드포인트에 gpt-5.6-luna 호출 결과 200, chat.completion 정상 생성. 인증은 Bearer 접두 없이 키 원문을 Authorization 헤더에 넣는다. 모델은 날짜 스냅샷으로 해석된다(gpt-5.6-luna-2026-07-09). Azure 콘텐츠 필터가 켜져 있다. (원 ID: GLV-ANS-023)

#### Q30 JSON 모드는 지원 가정으로 진행

JSON 모드(response_format)는 지원된다고 가정하고 진행한다. 미지원·형식 위반 시 JSON 복구·강등 배선이 받는다. 실검증은 반입 체크리스트로 이월한다. (원 ID: GLV-ANS-024)

### 3.2 과업 지시 (과업지시 초안_1.xlsx, 추진과업 개요 시트. 2026-09-16 발주자 설명 포함)

#### Q31 종합 인텔리전스 서비스 구현

현대차 생산·판매·재고 데이터 + 블룸버그 데이터 + 뉴스 API 데이터를 활용한 종합 인텔리전스 서비스를 구현한다. VODA(태블로) 기반의 데이터분석 화면 + AI 서비스를 결합한 신규 서비스 양식이다. 신규개발이며 디자인 고급화·개발사 화면 제안·AI 인사이트 모두 "필요"다. 화면 본수 2본. 이 항목의 뜻은 [[#Q55]]로 보강됐다. (원 ID: 과업지시 G10)

#### Q54 대시보드 3본과 각각의 AI 인사이트 리포트

현대차 CDO 인입 생산·판매·재고 실적을 기반으로 신규 대시보드를 각각 1본씩 Dfocus가 기획해 제안한다(총 3본). 셋 다 디자인 고급화·개발사 화면 제안·AI 인사이트가 "필요"다. 참고자료 A(현대차 데이터인사이드의 신차 판매 대시보드·재고 대시보드)를 참조하되 똑같이 만들지 말고 디자인 고급화까지 입혀 별도로 구현한다. 똑같이 만들면 데이터까지 맞춰야 하는데 쉽지 않다. 이 3본 각각에 Nabi Agent를 통해 AI 인사이트 리포트를 붙인다. (원 ID: 과업지시 G3·G4·G5, F열, 참고 시트 A. 2026-09-16 발주자 설명)

#### Q55 종합 리포트는 대시보드 3본을 엮은 것, 외부요인은 여기서만 결합

개요 시트의 화면은 G10 종합 인텔리전스 서비스의 화면이다. 이것은 생산·판매·재고 대시보드 3본을 하나의 리포트로 엮어 보여 주는 것이며, 외부요인(뉴스·블룸버그)은 이 종합 리포트에서만 결합한다. 대시보드 3본 각각의 AI 인사이트에는 외부요인이 붙지 않는다. 범용 결합 서비스가 아니라 구조를 딱 잡고 가는 것이다. (원 ID: 2026-09-16 발주자 설명, 유저 전달)

#### Q56 개요 시트의 화면 구성은 고정이 아니다

인텔리전스 서비스 개요 시트의 화면 구성은 디자인이 그런 식으로 갔으면 좋겠다는 방향이다. 거기 보이는 카드들을 정확히 그대로 보여 달라는 것이 아니다. 우리가 가진 데이터의 구조를 살펴보고 실제로 되는 것으로 간다. (원 ID: 2026-09-16 발주자 설명, 유저 전달)

#### Q57 참고자료 A의 지표 구성

참고자료 A는 현대차가 자체 서비스하는 대시보드 2본이다. 신차 판매 대시보드: 회사·권역·국가·제네시스·일자 필터, 권역·국가별 소매 현황 막대와 지도, 선적·도매·소매 각각의 YTD·MTD 실적과 진도율, 전년 대비(YoY)·전월 대비(MoM), 당월 판매량·계획량·전년월 판매량 월별 추이, 차종그룹별 소매 Top 10(YTD·MTD), P/T별 소매 비중, 소매유형별(개인·플릿·데모) 비중. 재고 대시보드: 현지 재고·장기 재고·항해중 재고의 당월값과 전월·전년 대비, 권역별 현지 재고, 현지·장기 재고 추이(YoY·MoM·MOS 12개월), 법인재고·딜러재고 월별 스택, P/T별 재고, 모델별 현지·장기 재고 Top 10. (원 ID: 과업지시 참고 시트 A 이미지 2장)

#### Q52 기존 대시보드는 사업계획 대신 전년 동기 대비로 구성

기존 VODA 대시보드(국내공장 생산, 국내 판매, 해외공장 생산)는 엑셀 데이터 기반이던 것을 완성차 IF 데이터로 교체하고 일부 필드를 바꾼다. 사업계획 데이터가 없으므로 전년 동기 대비로 구성을 변경한다. 이 대시보드 자체는 이 원장 범위 밖이지만, 계획 데이터 부재 시 전년 동기 대비를 기준으로 삼는다는 발주자 입장이 인텔리전스의 이상탐지 기준에도 그대로 적용된다. (원 ID: 과업지시 G7, G8, G9)

### 3.3 화면 구성 요구 (과업지시 초안_1.xlsx, 인텔리전스 서비스 개요 시트. 발주자가 Dfocus 시안에 단 수정 메모)

시안은 시장지표 바(GPR·Brent·BDI·SCFI), AI 요약 헤드라인("상관관계 확인 · 인과관계 미확정" 배지), 도메인 상태 3카드(생산·판매·재고, 신호등), 판매 상세(국가별 당월 실적·전년동월 대비 표, 각주 번호가 달린 AI 브리핑, 근거 칩, 시장 데이터 원값 펼치기), 조기경보 워치리스트 카드(정형 신호·비정형 신호·관련법인 태그·상세 인사이트 보기)로 구성돼 있다. 발주자 메모는 이 시안을 본 뒤의 지시다. [[#Q56]]에 따라 아래 메모는 디자인 방향이며, 카드 구성은 데이터 구조로 판단해 바꿀 수 있다.

#### Q32 레이아웃 순서: 헤드라인, 도메인 상태, 워치리스트

레이아웃 순서를 바꾼다. 첫째 AI 요약(오늘의 헤드라인), 둘째 생산·판매·재고별 특이사항(도메인 상태), 셋째 조기경보 워치리스트 순이다. (원 ID: 개요 B2, C3, C4, C7)

#### Q33 도메인 상태는 접고 펼 수 있어야 한다

생산·판매·재고별 특이사항 영역은 접고 펼 수 있어야 한다. (원 ID: 개요 C5)

#### Q34 핵심 키워드와 근거는 강조 표시

글이 너무 많아서 핵심을 파악하는 데 어려움이 있다. 핵심 키워드나 근거에는 굵은 볼드체 + 노란 음영 등으로 강조한다. (원 ID: 개요 C6)

#### Q35 워치리스트는 정형 흐름과 비정형 데이터의 관련도가 높은 목록

조기경보 워치리스트는 생산·판매·재고 데이터의 흐름과 실제 비정형 데이터(뉴스, 블룸버그 등) 간 관련도가 높을 것으로 예상되는 리스트를 표현한다. 아마 사전 관찰이 필요한 국가 정도로 의미를 부여한다. (원 ID: 개요 C8, C9)

#### Q36 워치리스트 국가와 실적을 결합할 때 AI 내러티브 발동

워치리스트 국가 + 생산·판매·재고 데이터 결합 시 인사이트 내러티브 AI 발동이 필요하다. (원 ID: 개요 C10)

#### Q37 관련 글로비스 법인에 신호등으로 영향도 표시

관련 글로비스 법인에 신호등 정도로만 영향도 이팩트를 주면 어떨까. (원 ID: 개요 C11)

#### Q38 워치리스트 근거는 접었다 펼치거나 링크로 이동

워치리스트에 그 이유가 되는 뉴스 토막 정보나 블룸버그 같은 근거가 접었다 펼쳤다 혹은 링크 이동이 가능해야 한다. (원 ID: 개요 C12)

### 3.4 서비스 목표 (기본계획 pptx, 과업범위 3)

#### Q39 AI 기반 이상징후 즉각 알림

생산·판매 관련 데이터가 정상 범주를 이탈하면 알림 + AI 원인분석 초안을 발송한다. 예: 법인, 국내 공장별 완성차 생산·판매 현황 및 동향 분석. (원 ID: 기본계획 슬라이드 10-1)

#### Q40 발생 외부 이슈 즉각 연계 분석

#### Q44 완성차 데이터 범위

생산은 생산실적(일별·월별·현시점 누적·연 누적). 판매는 판매실적·오더실적·재고현황·MOS이며 프로세스 단계(선적, 도매, 소매 등), 위치(현지재고, 대리점, 딜러 등), 진행상태(항해 중, 선적 대기 등)로 나뉜다. 생산·운영계획과 판매계획은 CDO 내부 이슈로 내년에 연계 가능하다. 기준정보 차원은 국내/해외, 생산법인, 공장, 내수/수출, 차종그룹, 세부차종, 승/상용, CBU/CKD, 차급, P/T, 제네시스, N시리즈, 기준일자(생산)와 대권역, 권역, 지역, 국가, 판매법인, 대리점, 생산법인, 차종 계열(판매)이다. (원 ID: 기본계획 슬라이드 6)

#### Q45 완성차 IF 레이아웃 확정과 3개월치 수신

현대차와 최종 협의된 전송 데이터 항목(IF 레이아웃)을 받았다. 생산 17열(차원 15 + 측정값 production_vehicle_cnt), 판매·재고 23열(차원 15 + 측정값 7: 선적·공식 도매·소매, 법인재고·딜러재고·항해중재고·선적대기재고)이다. 생산에는 현대/기아 구분코드가 있어 기아 공장이 포함된다. 실데이터는 3개월치(생산 2026-07-01~09-30 45,172행, 판매·재고 2026-06-30~09-09 56,896행)를 발주자가 데이터인사이드에서 일일이 조회해 엑셀로 받은 뒤 재정렬한 수작업 추출본이며, 자동 연계는 아직 없다. (원 ID: 메일_03, 메일_04, 현대차 전송 데이터 항목.xlsx)

#### Q46 외부 데이터 수신 현황

#### Q47 Marklines는 전세계 OEM 비교용, 1~2개월 지연

Marklines는 글로비스 GBP에서 제공해 줄 데이터로 전세계 OEM 사들의 생산·판매 실적이다. 전세계 OEM 사들의 실적도 함께 비교함으로써 인사이트를 받을 수 있지 않을까 해서 추가한다. 다만 현재 기준 1개월에서 2개월 정도 늦게 들어온다는 제약이 있다(9월이면 7월 데이터 인입). 설계에 참고해 달라. 수신 샘플은 country, car_group, maker_brand, vehicle_type, segment, model_name, powertrain, sales_year, sales_month, sales_count 구조이며 2019년 China·Japan 분량이다. (원 ID: 메일_02)

#### Q48 DBA 파이프라인 구성과 실행 결과, 워치리스트 10개국 확인 요청

자사 DBA가 공유한 분석 로직은 화면 4단계와 1:1 대응한다. 1) 계획 데이터 없이 전년동월 대비로 이상탐지(당월 0이면 -100% 확정), 2) 도메인별 카테고리 라우팅으로 뉴스 검색과 impact_score 랭킹, 3) CBU/CKD 비중 계산, 4) 정형 이상탐지와 비정형 근거가 둘 다 있는 국가만 선별해 CBU 비중으로 RED/YELLOW 신호등 결정, 5) 인용 번호가 달린 템플릿 문장(실 서비스에서는 LLM 호출로 대체). 실행 결과는 아랍에미리트 RED(CBU 100%, 항해중재고 570대), 오만 RED(CBU 100%, 418대), 파키스탄 YELLOW(CBU 0.1%, 1대). 임계값(YOY_ANOMALY_THRESHOLD, MIN_EVIDENCE_IMPACT 등)은 초안이라 현업 검토가 필요하다. 이전 3개국 버전은 ISO 매핑이 3개국뿐이어서 축소된 결과였고, 179개국 전체 매핑을 적용하면 러시아·바레인·파나마·예멘·지부티·카타르·중국까지 총 10개국이 조건을 충족한다. 대시보드 워치리스트도 10개국 기준으로 갱신할지 확인을 요청했다. (원 ID: 메일_05, ai_intelligence_pipeline.py)

#### Q49 판매법인은 26개국만 직영, 나머지는 딜러 시장

크로스워크 02 시트에 사내 판매법인코드와 직영법인 보유 여부를 추가했다. 원본 판매데이터 기준 179개국 중 26개국만 현대차 직영 판매법인을 보유하고(HMA 미국, HMD 독일, HMUK 영국 등), 나머지 153개국(중동 전역 포함)은 딜러·에이전트 운영시장이라 법인코드가 없다. 이는 데이터 누락이 아니라 실제 사업구조다. (원 ID: 크로스워크 00_설계개요)

#### Q50 뉴스 API 데이터 구조

뉴스는 사내 카테고리 8종(MRT 해운·항로·항만, GEO 지정학·제재·분쟁, NDS 자연재해, ENR 에너지·원자재, FWD/KD 포워딩·KD, REG 규제·비용·보험, OEM 생산·판매, FVL 완성차 물류)으로 분류되고, 국가는 ISO alpha-3 다중 태그(llm_country_iso3, 쉼표 구분)로 붙는다. 점수는 impact_score, weighted_impact_score, index_score(가공본) 또는 normalized_score(원본)다. 본문은 영문 번역(llm_body_en), 요약(llm_summary), 분류 사유(llm_reason, 한글), 키워드, 출처명, URL을 갖는다. 가공본과 원본은 컬럼 구성이 다르다. 원본에는 title·image_url·index_score가 없고 normalized_score가 있으며, published_at_kst가 시각 일부만 남아 있고 published_date_kst가 따로 있다. 크로스워크 08 시트의 라우팅은 생산=OEM·FWD/KD, 판매=MRT·GEO·ENR·NDS·REG, 재고=MRT·FWD/KD다. (원 ID: news_article_results.csv, news_article_results_raw.csv, 크로스워크 01·08)

#### Q51 블룸버그 데이터 구조

블룸버그 4파일 31시트는 데이터서비스팀이 2026-08-21 터미널에서 추출한 것이다. 시계열 시트(BDI·CCFI·SCFI·컨테이너 운임, 유가·LME·환율·금리·PMI·GPR·GSCPI 등)는 전부 IDENTIFIER × DATE → PX_LAST의 롱 포맷이라 한 테이블로 통합할 수 있다. 예외로 파일 (2)의 글로비스 재무 3시트(대차대조표·손익계산서·기업가치)는 연도·분기 × 계정 항목의 와이드 포맷이다. IDENTIFIER 컬럼이 세부 정보다(예: BDI 시트의 BITY Index는 정유제품 운송 운임지수). 크로스워크 06 시트가 시트별로 도메인과 사내 뉴스 카테고리를 relatedMatch로 연결했고, 주식·투자자 동향 6개 시리즈는 미분류다. 파일 (4)의 CO1_BDI_SCFI 시트가 호르무즈 사례에 실사용됐다. (원 ID: 메일_01, 블룸버그데이터추출(1)~(4), 크로스워크 06)

## 5. 첫 프로젝트

3층 구조([[#Q54]] [[#Q55]]) 전체가 범위다. 1층 대시보드는 태블로 팀 몫이고, 2층은 브리핑 갈래 설계로 이미 닫혀 있으며, 이 원장의 하류 문서는 3층 종합 리포트와 2층→3층 연결을 설계한다. 개요 시트의 메모([[#Q32]]~[[#Q38]])는 디자인 방향([[#Q56]])이고, 기본계획 과업 3의 네 목표([[#Q39]]~[[#Q42]]) 중 이 리포트로 닿는 것은 이상징후 원인분석, 외부 이슈 연계분석, 영향요인 조기 포착이다. 자사 DBA 파이프라인([[#Q48]])이 외부요인 판정 로직의 출발점이다. 이상징후 알림 발송([[#Q39]])의 채널은 확인 전이다.
