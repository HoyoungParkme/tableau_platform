# PRD — 제품 요구

## 1. 목표

#### G1 대시보드 3본 위에 서는 종합 브리핑

현업 담당자가 VODA에서 생산·판매·재고 대시보드 3본을 보고, 각 대시보드의 AI 인사이트(2층)를 읽고, 종합 리포트(3층)에서 세 도메인의 변동과 그 원인 후보를 한 화면에서 본다. 근거: [[TBL-RFQ-001#Q1]] [[TBL-RFQ-001#Q54]] [[TBL-RFQ-001#Q55]]

#### G2 변동을 먼저 찾고, 원인을 뉴스에서 찾는다

대시보드 데이터에서 감지된 변동을 출발점으로 삼아 뉴스·시장 데이터에서 원인 후보를 찾고, 그 연관을 근거와 함께 보여 준다. 뉴스가 출발점이 아니다. 근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q39]] [[TBL-RFQ-001#Q40]]

#### G3 감지와 후보는 코드, 연관 판단과 문장은 LLM

변동 감지와 원인 후보 좁히기는 결정적 코드가 하고, LLM은 후보 안에서 연관을 판단하고 설명하고 문장을 쓴다. 화면의 모든 주장은 근거 행까지 추적된다. 근거: [[TBL-RFQ-001#Q38]] [[TBL-RFQ-001#Q48]]

#### G4 외부 데이터의 자산화

뉴스·블룸버그·Marklines와 현업 피드백을 우리 DB에 쌓는다. 오늘의 리포트 재료이자 다음 사업(예측)의 학습 데이터다. 근거: [[TBL-RFQ-001#Q43]] [[TBL-RFQ-001#Q46]]

#### G5 폐쇄망 납품 형상

폐쇄망 3컨테이너(postgres, backend, frontend), 사내 H-chat, VODA 단독 주소로 납품한다. 근거: [[TBL-RFQ-001#Q10]] [[TBL-RFQ-001#Q11]] [[TBL-RFQ-001#Q14]]

## 3. 요구사항

### 3.1 입력: 2층 연결과 외부 데이터 적재

#### R25 대시보드 스냅샷의 변동 판정을 3층 입력으로 받는다

근거: [[TBL-RFQ-001#Q54]] [[TBL-RFQ-001#Q55]] [[TBL-RFQ-001#Q57]]

2층(브리핑 갈래)이 대시보드 3본에서 매일 만드는 지표 스냅샷과 변동 판정을 3층의 정형 입력으로 읽는다. 3층은 대시보드 수치를 다시 집계하지 않는다. 대시보드가 곧 집계 정의다. 국가 단위 변동을 만들려면 대시보드에 국가 차원 시트가 있어야 한다(미결). 없으면 [[#R1]]의 IF 집계로 보완한다.

- [ ] 대시보드 3본 각각의 스냅샷 판정(지표, 값, 비교값, 기준 방식, 판정)이 도메인·국가·일자 키로 조회된다
- [ ] 3층이 만든 도메인 상태 수치가 대시보드 화면 수치와 일치한다
- [ ] 국가 차원 시트가 없는 지표는 IF 집계 보완임이 결과에 표시된다

#### R1 완성차 IF 원장 적재 (보조)

근거: [[TBL-RFQ-001#Q44]] [[TBL-RFQ-001#Q45]]

IF 레이아웃(생산 17열, 판매·재고 23열)을 일별 원장으로 적재한다. 역할은 둘이다. 대시보드에 없는 국가 단위 집계의 보완([[#R25]])과 CBU/CKD 유도([[#R10]]). 기준일자 단위 멱등 재적재, 3개월치 백필, 파일 업로드.

- [ ] IF 컬럼 영문명이 테이블 컬럼명과 1:1로 같다
- [ ] 3개월 샘플 적재 후 행수가 원본과 일치한다(생산 45,172행, 판매·재고 56,896행)
- [ ] 같은 기준일자를 두 번 적재해도 행이 늘지 않는다
- [ ] 결측(`-`)은 NULL, 미래 골격 행은 계수 후 판정 제외

#### R2 마스터·크로스워크 이관

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q49]] [[TBL-RFQ-001#Q50]] [[TBL-RFQ-001#Q51]]

크로스워크 9시트를 테이블로 옮긴다. 국가(179), 생산공장, 뉴스 카테고리, 도메인 라우팅, 블룸버그 매핑. 판매 국가코드는 대리점 앞 3자리. 미매핑은 목록에 쌓는다.

- [ ] 판매→국가, 생산→국가, 뉴스→국가 매칭률을 적재마다 기록한다(현재 177/189, 39/69, 134/148)
- [ ] 미매핑 값이 목록으로 조회되고 엑셀 재업로드로 갱신된다

#### R3 뉴스 기사 적재

근거: [[TBL-RFQ-001#Q50]]

뉴스 API 결과를 기사 단위로 적재한다. 카테고리 8종, ISO3 다중 태그 분해, 점수, 요약, URL, 게시 시각. 가공본·원본 두 스키마 모두 읽고 정본은 가공본. FVL을 라우팅에 배정.

- [ ] result_id로 중복 제거, 국가 태그 분해, 라우팅 미배정 카테고리 0종
- [ ] 게시 시각 훼손 행은 일 단위로 대체하고 정밀도 플래그

#### R4 기사를 사건으로 묶고, 변동과 연결된 사건만 LLM이 이름 붙인다

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q40]] [[TBL-RFQ-001#Q48]]

같은 국가(해협 귀속 포함), 같은 카테고리, 같은 시간창(기본 7일)의 기사를 규칙으로 사건 하나로 묶는다. 이건 전량 매일 한다. LLM 명명(제목·유형·심각도)은 [[#R26]]에서 어떤 변동의 원인 후보로 뽑힌 사건에만 한다. 그 외 사건은 대표 기사 제목을 쓴다.

- [ ] 호르무즈 기사 460건이 사건 소수로 묶인다
- [ ] 모든 사건에서 기사 URL로 역추적된다
- [ ] LLM 명명 호출 수가 "후보로 뽑힌 사건 수"를 넘지 않는다

#### R5 블룸버그 시계열 통합

근거: [[TBL-RFQ-001#Q51]]

시계열 28시트를 identifier × date → value 한 테이블로. 재무 3시트는 원본 보존만. 지표 바 4종 최신값·기준일 조회.

- [ ] 28시트 적재, 미분류 6개 표시, 4종 최신값 조회

#### R6 Marklines 적재

근거: [[TBL-RFQ-001#Q47]]

월별 OEM 실적. 기준월과 인입일 저장. 실데이터 전에는 비노출.

- [ ] 샘플 적재, 기준월 표기, 없어도 리포트 생성

### 3.2 감지와 원인 탐색

#### R26 변동마다 원인 후보를 코드가 찾는다

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q40]] [[TBL-RFQ-001#Q50]]

[[#R25]]가 준 변동(도메인, 국가, 지표, 기간, 방향, 크기)마다 원인 후보를 결정적으로 뽑는다. 후보는 세 종류다. 그 국가(해협 귀속 포함)와 라우팅 카테고리, 시간창 안의 사건과 기사 상위 N. 같은 기간 시장지표의 변화(지표 바 4종 + 카테고리 연결 시리즈). 같은 국가의 다른 도메인 변동(예: 판매 급감과 재고 체류). 후보에는 ID가 붙고 판정 결과와 함께 저장된다.

- [ ] 후보 목록이 변동별로 저장되고 다시 돌리면 같은 후보가 나온다
- [ ] 후보가 0건인 변동도 목록에 남는다("원인 후보 없음")
- [ ] 후보 상한(기본 사건 5, 기사 10, 지표 6)이 설정값이다

#### R27 H-chat이 후보 안에서 연관을 판단하고 설명한다

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q36]] [[TBL-RFQ-001#Q41]]

변동 사실과 후보 목록을 H-chat에 보내 후보별 관련도(높음·중간·낮음·무관), 연관 설명, 인용할 후보 ID를 JSON으로 받는다. LLM은 후보 밖의 사실을 쓸 수 없고 인과 단정 어휘를 쓸 수 없다. 결과는 변동별로 저장되고 화면에는 "상관관계 확인 · 인과관계 미확정" 배지가 붙는다. 이것이 데이터 변동과 뉴스 사이의 공백을 메우는 자리다.

- [ ] 출력의 모든 인용이 입력 후보 ID 안에 있다(검증기)
- [ ] 관련도 높음이 하나도 없으면 "원인 후보 확인 안 됨"으로 표시된다
- [ ] LLM 실패 시 후보 목록만 관련도 없이 표시된다(강등)

#### R7 국가 × 일자 결합 테이블

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q48]]

정형(2층 스냅샷 판정 + IF 보완 집계), 사건, 시장을 국가 × 일자 한 줄로 모은다. 감지·후보·연관의 재현 근거이자 2차 학습 테이블이다.

- [ ] 한 행에 도메인별 변동 판정, 재고 4종, CBU 비중, 사건 수·최대 심각도, 시장지표 as-of 값이 있다
- [ ] 기준일마다 179개국 행이 존재한다

#### R8 변동 감지 기준

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q52]]

변동 감지는 2층 스냅샷 판정을 따른다. 3층은 임계값을 재적용하지 않고, 국가 단위 보완 집계([[#R1]])에만 자체 임계값을 쓴다. 비교 기준은 전년동월 대비, 없으면 전월 대비로 강등하고 기준 방식을 표시한다.

- [ ] 변동마다 기준 방식(YoY/MoM)과 비교 기간이 저장된다
- [ ] 보완 집계의 임계값은 설정값이다

#### R9 재고 체류 신호

근거: [[TBL-RFQ-001#Q44]] [[TBL-RFQ-001#Q48]]

항해중·선적대기 재고 비중을 변동의 한 종류로 다룬다. 중복 적재 의심 일자는 플래그와 "데이터 확인 필요".

- [ ] 재고 변동이 [[#R26]]의 후보 탐색 대상이 된다

#### R10 차종 노출 (CBU/CKD)

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q44]]

국가별 CBU 비중을 생산 IF의 모델코드로 유도한다. 판매 IF에는 없다. 유도 실패는 "노출 미확인". 노출은 연관 판단([[#R27]])의 입력이자 신호등 규칙의 입력이다.

- [ ] 유도 비율 기록(현재 194/230), 실패 국가는 RED 불가

#### R11 워치리스트는 변동 목록을 국가로 묶은 것

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q36]] [[TBL-RFQ-001#Q48]]

워치리스트는 별도 판정이 아니라 [[#R26]]·[[#R27]]의 결과를 국가별로 묶어 정렬한 것이다. 신호등은 규칙이다. 관련도 높음 후보가 있고 노출이 CBU면 RED, 관련도 높음이 있으면 YELLOW, 변동만 있고 후보가 없거나 무관이면 목록에는 남되 신호등 없음. 임계값과 규칙은 설정값이다.

- [ ] 변동은 있는데 원인 후보가 없는 국가도 목록에 "원인 미확인"으로 남는다
- [ ] 3개월 샘플 + 뉴스로 돌리면 UAE·오만·파키스탄이 관련도 높음으로 나온다(골든 배치)

#### R12 관련 법인 신호등

근거: [[TBL-RFQ-001#Q37]] [[TBL-RFQ-001#Q49]]

국가 → 글로비스 법인 매핑이 있으면 태그, 없으면 "법인 미매핑". 현대차 판매법인으로 대체하지 않는다.

- [ ] 매핑 없어도 오류 없이 표시, 들어오면 다음 배치부터 반영

#### R13 시점 고정과 재현

근거: [[TBL-RFQ-001#Q41]]

리포트는 생성 시점 스냅샷 기준. 변동·후보·연관 판단을 함께 저장해 재생성 시 후보가 같다. LLM 문장만 달라질 수 있다.

- [ ] 리포트마다 기준 일시, 데이터 최신일, 후보 목록이 저장된다

#### R28 현업 피드백을 라벨로 쌓는다

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q53]]

워치리스트 항목마다 현업이 "맞다·아니다·모르겠다"를 누를 수 있다. 사번과 시각을 함께 저장한다. 판정에는 즉시 반영하지 않고 2차(예측)의 라벨과 임계값 보정 재료로 쓴다.

- [ ] 피드백이 변동·후보·연관 판단 ID와 함께 저장된다
- [ ] 월별 동의율이 조회된다

### 3.3 리포트 생성

#### R14 LLM 입력은 판정된 사실과 고정된 후보만

근거: [[TBL-RFQ-001#Q36]] [[TBL-RFQ-001#Q41]] [[TBL-RFQ-001#Q43]]

## 6. 결정사항

상태 "제안"은 유저 승인 전, "확정(날짜)"은 승인 후. 2026-09-15 A 방식 채택으로 6.6·6.7 확정. 2026-09-16 발주자 설명으로 6.12 확정, 유저 방향으로 6.11·6.13 제안.

### 6.1 ML(학습 모델)은 1차에 쓰지 않는다

상태: 제안. 학습 데이터 없음(완성차 3개월, 라벨 0건), 예측 대상 지표가 IF에 없음, 발주자 미요구, 운영 인력 미확인. 재검토 조건: 결합 테이블 12개월 + [[#R28]] 피드백 300건 + 발주자의 예측 지표 요구. 상세 근거와 자원 추정은 v3 기록과 같다.

### 6.2 LLM은 세 역할에만 쓴다

상태: 제안 (v3의 두 지점에서 세 역할로 개정)

| 역할 | 입력 | 출력 | 실패 시 |
|:--|:--|:--|:--|
| 1. 사건 명명 ([[#R4]]) | 후보로 뽑힌 사건의 기사 상위 5 | 제목, 유형, 심각도 | 대표 기사 제목 |
| 2. 연관 판단 ([[#R27]]) | 변동 사실 + 후보 목록(ID) | 후보별 관련도, 설명, 인용 ID | 후보 목록만 표시 |
| 3. 문장 생성 ([[#R15]]) | 판정·연관 결과 구조체 | 헤드라인, 도메인 상태, 카드 요약 | 템플릿 문장 |

판정(변동 감지), 후보 좁히기, 랭킹, 매핑, 수치 계산에는 쓰지 않는다. 물량: 명명은 후보 사건만이라 일 수십 건, 연관은 변동 수(일 수십), 문장 약 65. 합계 일 20만~40만 토큰.

### 6.3 사건은 규칙으로 전량 묶고, 명명은 후보만

상태: 제안 (개정). 야간에 국가+카테고리+시간창 규칙으로 전량 묶어 사건 저장소를 유지한다(검색 대상). LLM 명명은 변동의 후보로 뽑힌 사건에만 한다. 임베딩 클러스터링과 전량 LLM 판독은 탈락(이유는 v3와 같다). 해협 이슈는 해협→인접국 표로 귀속.

### 6.4 변동 감지 기준은 2층 판정, 비교는 전년동월 우선

상태: 제안 (개정). 3층은 2층 스냅샷 판정을 그대로 받는다. 보완 집계에만 자체 임계값. 전년동월 없으면 전월 대비 강등. 사업계획 대비는 데이터 연계 후.

### 6.5 원인 후보 검색은 구조화 조회, 벡터 RAG 없음

상태: 제안. 후보는 국가·카테고리·시간창·심각도로 SQL 조회. 기본계획의 "전용 RAG"는 이 구조화 조회와 후보 한정 LLM 입력을 뜻하는 것으로 설명한다. 대화형 질의가 2차에 오면 벡터 검색 재검토.

### 6.6 외부 데이터는 전부 적재하고 판정은 우리 DB에서 한다

상태: 확정 (2026-09-15). 근거는 v3와 같다.

### 6.7 결합 단위는 국가 × 일자

상태: 확정 (2026-09-15). 근거는 v3와 같다.

### 6.8 워치리스트는 변동 목록의 국가 묶음이다

상태: 제안 (개정). v3의 "정형 AND 비정형 교차 확인만"에서 바뀌었다. 변동이 있으면 목록에 오르고, 원인 후보와 관련도가 신호등을 정한다. 변동 없이 뉴스만 급증한 국가는 오르지 않는다(언급빈도 편향 차단은 유지).

### 6.9 뉴스 수집과 1차 분류는 발주자 시스템

상태: 제안. v3와 같다.

### 6.10 리포트는 배치로만, 사용자 새로고침 없음

상태: 제안. v3와 같다.

### 6.11 데이터가 먼저, 뉴스는 원인 탐색

상태: 제안 (2026-09-16 유저 방향)

| 선택지 | 내용 | 판단 |
|:--|:--|:--|
| A. 데이터 주도 | 대시보드 변동 감지 → 그 변동에 대해 뉴스·시장에서 원인 후보 → LLM 연관 판단 | 선택 |
| B. 뉴스 주도 | 뉴스 사건화 → 데이터로 확인 → 예측 (ML 연구원 메모) | 탈락 |

근거: 발주자 요구가 "데이터 흐름과 비정형의 관련도"이고 대시보드가 이미 있다. 뉴스 처리량이 전량에서 변동 건수만큼으로 줄어 LLM 비용과 배치 시간이 내려간다. 예측에 필요한 과거 데이터가 없다. 뉴스 주도는 언급빈도 편향(미국·이란 상위)을 만든다.

공백: "이 변동이 이 뉴스와 관련 있는가"는 규칙만으로 답이 나오지 않는다. 그래서 감지·후보는 코드, 연관 판단은 H-chat([[#R27]]), 결과는 후보 ID 인용과 배지로 가둔다. 현업 피드백([[#R28]])이 이 판단의 정확도를 측정하고 2차 라벨이 된다.

재검토 조건: 피드백 동의율이 50% 미만이면 후보 규칙(카테고리 라우팅, 시간창)을 먼저 조정하고, 그래도 낮으면 연관 판단 방식을 재검토한다.

### 6.12 화면 구성은 고정이 아니다

상태: 확정 (2026-09-16 발주자 설명, [[TBL-RFQ-001#Q56]]). 개요 시트는 디자인 방향. 표시 항목은 데이터 구조로 판단해 [[#R19]]로 확정한다. 법인 신호등은 매핑 수령 전까지 비운다.

### 6.13 정형 신호의 원천은 2층 스냅샷, IF 집계는 보완

상태: 제안

| 선택지 | 내용 | 판단 |
|:--|:--|:--|
| A. 2층 스냅샷 판정을 읽는다 | 대시보드가 집계 정의. 3층은 재집계하지 않음 | 선택 |
| B. IF 원장에서 3층이 독자 집계 | 대시보드와 정의 불일치 위험 | 보완으로만 |

근거: 발주자 구조가 "대시보드 3본을 엮은 리포트"다. 같은 국가의 판매 급감이 대시보드와 리포트에서 다른 숫자로 보이면 신뢰가 무너진다. 다만 대시보드에 국가 시트가 없으면 뉴스와 만날 축이 없으므로 IF 집계를 보완으로 둔다.

필요한 것: 브리핑 갈래의 지표 스냅샷·판정 테이블을 3층이 읽는 인터페이스. 대시보드 3본의 국가 차원 시트 확인(미결).
