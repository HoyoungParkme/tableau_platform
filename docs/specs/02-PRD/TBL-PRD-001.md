# PRD — 제품 요구

## 1. 목표

#### G1 열면 바로 보이는 결합 브리핑

현업 담당자가 VODA에서 인텔리전스 화면을 열면 완성차 실적과 외부 데이터(뉴스, 블룸버그, Marklines)를 결합한 AI 브리핑을 질문 없이 본다. 근거: [[TBL-RFQ-001#Q1]] [[TBL-RFQ-001#Q6]] [[TBL-RFQ-001#Q31]]

#### G2 국가 단위 조기경보

외부 이슈가 글로비스 실적에 미치는 영향을 국가 단위로 조기 포착해 워치리스트로 보여준다. 근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q40]] [[TBL-RFQ-001#Q42]]

#### G3 판정은 코드, 문장은 LLM

모든 수치 판정은 결정적 코드가 하고 LLM은 문장만 쓴다. 화면의 모든 주장은 근거 행까지 추적된다. 근거: [[TBL-RFQ-001#Q38]] [[TBL-RFQ-001#Q48]]

#### G4 외부 데이터의 자산화

완성차·뉴스·블룸버그·Marklines를 우리 DB에 적재해 발주자 자산으로 쌓는다. 오늘의 브리핑 재료이자 다음 사업(예측)의 학습 데이터다. 근거: [[TBL-RFQ-001#Q43]] [[TBL-RFQ-001#Q46]]

#### G5 폐쇄망 납품 형상

폐쇄망 3컨테이너(postgres, backend, frontend), 사내 H-chat, VODA 단독 주소로 납품한다. 근거: [[TBL-RFQ-001#Q10]] [[TBL-RFQ-001#Q11]] [[TBL-RFQ-001#Q14]]

## 3. 요구사항

### 3.1 데이터 적재

#### R1 완성차 IF 원장 적재

근거: [[TBL-RFQ-001#Q44]] [[TBL-RFQ-001#Q45]]

현대차 IF 레이아웃(생산 17열, 판매·재고 23열)을 컬럼 변환 없이 일별 원장으로 적재한다. 기준일자 단위로 멱등하게 재적재할 수 있어야 하고, 이미 받은 3개월치를 넣는 백필 경로가 처음부터 있어야 한다. 자동 연계 전에는 엑셀 파일 업로드로 받는다.

- [ ] IF 컬럼 영문명이 테이블 컬럼명과 1:1로 같다
- [ ] 3개월 샘플 적재 후 행수가 원본과 일치한다(생산 45,172행, 판매·재고 56,896행)
- [ ] 같은 기준일자를 두 번 적재해도 행이 늘지 않는다
- [ ] 문자열 결측(`-`)은 NULL로 저장하고 결측 건수가 적재 이력에 남는다
- [ ] 미래 날짜의 빈 골격 행(생산 9/15~9/30)은 적재 이력에 "빈 행"으로 계수되고 판정에서 제외된다

#### R2 마스터·크로스워크 이관

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q49]] [[TBL-RFQ-001#Q50]] [[TBL-RFQ-001#Q51]]

자사 DBA 크로스워크 9시트를 테이블로 옮긴다. 국가(사내 코드 ↔ ISO3, 179개국, 직영법인 여부), 생산공장 → 국가, 뉴스 카테고리, 도메인 라우팅, 블룸버그 시계열 → 카테고리. 판매 데이터의 국가코드는 대리점 코드 앞 3자리에서 유도한다. 매핑이 없는 값은 지어내지 않고 미매핑 목록에 쌓는다.

- [ ] 판매 → 국가 매칭률과 생산 → 국가 매칭률을 적재 때마다 계산해 기록한다(현재 177/189, 39/69)
- [ ] 미매핑 값(국가 13종, 기아 공장 30종 등)이 목록으로 조회된다
- [ ] 크로스워크 엑셀을 다시 올리면 매핑이 갱신되고 판정 결과가 바뀌는 국가가 표시된다

#### R3 뉴스 기사 적재

근거: [[TBL-RFQ-001#Q50]]

뉴스 API 결과를 기사 단위로 적재한다. 카테고리 8종, ISO3 다중 국가 태그(기사 × 국가 정규화), 점수 3종, 요약, URL, 게시 시각. 가공본과 원본 두 스키마를 모두 읽되 정본 스키마는 가공본을 따른다. FVL 카테고리를 도메인 라우팅에 배정한다.

- [ ] 가공본 6,334건과 원본 고유 101,151건이 같은 테이블에 들어가고 result_id로 중복이 제거된다
- [ ] 국가 태그가 쉼표 분리된 기사가 국가별 행으로 풀린다
- [ ] 라우팅에 배정되지 않은 카테고리가 0종이다
- [ ] 게시 시각이 깨진 원본 행은 published_date_kst로 대체하고 정밀도 플래그가 남는다

#### R4 기사를 표준 사건으로 통합

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q40]] [[TBL-RFQ-001#Q48]]

같은 국가, 같은 카테고리, 같은 시간창(기본 7일)의 기사를 사건 하나로 묶는다. 사건은 유형, 세부유형, 위치(국가 또는 해협·항로), 상태, 심각도, 출처 수, 최초·최종 관측 시각, 기사 ID 목록을 갖는다. 사건 제목과 유형 판별에만 LLM을 쓴다(LLM 지점 1). 워치리스트 판정은 기사 수가 아니라 사건을 본다. 언급빈도가 위험도로 둔갑하는 편향을 여기서 끊는다.

- [ ] 호르무즈 관련 기사 460건이 사건 1건 또는 소수로 묶인다
- [ ] 모든 사건에서 기사 URL로 역추적할 수 있다
- [ ] 사건 상태는 관찰값이고 결과(영향)는 추정으로 구분 저장된다
- [ ] LLM 실패 시 규칙 묶음만으로 사건이 생성되고 제목은 대표 기사 제목으로 대체된다

#### R5 블룸버그 시계열 통합

근거: [[TBL-RFQ-001#Q51]]

시계열 시트 전부를 identifier × date → value 한 테이블로 적재한다. 크로스워크 06 매핑으로 identifier에 도메인과 카테고리를 붙인다. 글로비스 재무 와이드 시트 3장은 1차 브리핑 재료가 아니므로 원본 보존만 한다.

- [ ] 31시트 중 시계열 28시트가 한 테이블에 들어간다
- [ ] 미분류 6개 시리즈는 적재하되 브리핑 재료에서 제외 표시된다
- [ ] 시장지표 바에 쓰는 4종(GPR, Brent, BDI, SCFI)의 최신값과 기준일이 조회된다

#### R6 Marklines 적재

근거: [[TBL-RFQ-001#Q47]]

OEM 생산·판매 월별 실적을 적재한다. 데이터 기준월과 인입일을 함께 저장해 1~2개월 지연을 화면에 드러낸다. 실데이터가 들어오기 전에는 화면에 노출하지 않는다.

- [ ] 2019년 샘플이 스키마 검증용으로 적재된다
- [ ] 브리핑에 Marklines 값이 쓰이면 "기준월 YYYY-MM" 표기가 붙는다
- [ ] Marklines 데이터가 없어도 나머지 브리핑은 정상 생성된다

### 3.2 판정

#### R7 국가 × 일자 결합 테이블

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q48]]

정형(완성차 집계), 비정형(사건), 시장(블룸버그)을 국가 × 일자 한 줄로 모은 결합 테이블을 만든다. 판정 코드는 이 테이블만 읽는다. 1년치가 쌓이면 그대로 예측 학습 테이블이 된다.

- [ ] 결합 테이블 한 행에 판매 3종, 재고 4종, 생산, 사건 수·최대 심각도, 시장지표 값이 있다
- [ ] 배치가 끝나면 해당 일자 행이 179개국 전부에 대해 존재한다(데이터 없음도 행으로)

#### R8 정형 신호 판정

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q52]]

국가별 도매 실적을 전년동월 대비로 평가해 임계값 이하면 이상으로 판정한다. 발주자 원칙은 전년 동기 대비다. 과거 데이터가 없는 구간은 전월 대비로 강등하고 화면에 기준 방식을 명시한다. 당월 0이면 -100%로 확정한다.

- [ ] 같은 입력으로 다시 돌리면 같은 판정이 나온다
- [ ] 판정 결과에 기준 방식(YoY 또는 MoM)과 비교 기간이 저장된다
- [ ] 임계값은 코드 상수가 아니라 설정값이다

#### R9 재고 체류 신호

근거: [[TBL-RFQ-001#Q44]] [[TBL-RFQ-001#Q48]]

항해중재고와 선적대기재고를 총재고 대비 비중으로 보고 체류 신호를 낸다. 총재고는 4개 재고의 합이다.

- [ ] 국가별 항해중재고 대수와 비중이 판정 결과에 남는다
- [ ] 중복 적재가 의심되는 일자(9/8 2배 등)는 판정 전에 플래그가 붙고 브리핑에 "데이터 확인 필요"가 표시된다

#### R10 차종 노출 판정 (CBU/CKD)

근거: [[TBL-RFQ-001#Q48]] [[TBL-RFQ-001#Q44]]

국가별 물량이 완성차(CBU)인지 반조립(CKD)인지 비중을 계산한다. 판매 IF에 CBU/CKD가 없으므로 생산 데이터의 모델코드 ↔ CBU/CKD를 판매 모델코드에 붙여 유도한다. 유도가 안 되면 "노출 미확인"으로 둔다.

- [ ] 판매 모델코드 230종 중 CBU/CKD가 유도된 비율을 기록한다(현재 생산 ↔ 판매 모델코드 매칭 194/230)
- [ ] 유도 실패 국가는 신호등이 YELLOW 이하로 제한된다

#### R11 워치리스트 선별과 신호등

근거: [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q36]] [[TBL-RFQ-001#Q48]]

정형 이상([[#R8]] 또는 [[#R9]])과 사건 근거([[#R4]])가 같은 국가에서 교차 확인될 때만 워치리스트에 올린다. 신호등은 CBU 비중([[#R10]])으로 RED/YELLOW를 가른다. 임계값 4종(전년대비, 근거 심각도, 최소 근거 수, CBU 비중)은 설정값이며 초기값은 DBA 초안을 따른다.

- [ ] 정형 이상만 있고 사건이 없는 국가는 워치리스트에 오르지 않고 도메인 상태에만 반영된다
- [ ] 워치리스트 항목마다 정형 신호, 재고 신호, 사건, 근거 기사 상위 3건, CBU 비중이 저장된다
- [ ] 3개월 샘플 + 뉴스 가공본으로 돌리면 DBA 결과와 같은 국가 집합이 나온다(UAE, 오만, 파키스탄 포함)

#### R12 관련 법인 신호등

근거: [[TBL-RFQ-001#Q37]] [[TBL-RFQ-001#Q49]]

워치리스트 국가에 관련 글로비스 법인을 태그하고 신호등을 준다. 국가 → 글로비스 법인 매핑 테이블이 근거이며, 매핑이 없으면 "법인 미매핑"으로 표시한다. 현대차 판매법인 코드로 대체하지 않는다.

- [ ] 매핑 테이블이 비어 있으면 모든 카드가 "법인 미매핑"으로 뜨고 오류가 나지 않는다
- [ ] 매핑이 들어오면 재배치 없이 다음 배치부터 태그가 붙는다

#### R13 시점 고정과 재현

근거: [[TBL-RFQ-001#Q41]]

브리핑은 생성 시점의 데이터 스냅샷 기준으로 만들고, 그 시점을 지정해 다시 생성하면 같은 판정이 나온다. 이후 들어온 데이터가 과거 브리핑을 바꾸지 않는다.

- [ ] 브리핑마다 기준 일시와 사용한 데이터 최신 일자가 저장된다
- [ ] 과거 일자를 지정한 재생성이 당시 판정과 일치한다

### 3.3 브리핑 생성

#### R14 LLM 입력은 판정된 사실만

근거: [[TBL-RFQ-001#Q36]] [[TBL-RFQ-001#Q41]] [[TBL-RFQ-001#Q43]]

문장 생성(LLM 지점 2)의 입력은 판정이 끝난 구조체(국가, 정형 신호, 재고 신호, 노출, 사건, 근거 목록, 제약 문구)뿐이다. 원본 테이블을 넣지 않는다. 생성 후 숫자와 날짜가 입력과 같은지 대조하고, 불일치면 강등한다.

- [ ] 프롬프트 입력 크기가 워치리스트 항목당 2KB 이하다
- [ ] 생성문의 모든 숫자·날짜·국가명이 입력 구조체에 존재한다(검증기 통과)
- [ ] 검증 실패 시 템플릿 문장으로 강등되고 사유가 기록된다

#### R15 세 영역의 문장과 각주

근거: [[TBL-RFQ-001#Q32]] [[TBL-RFQ-001#Q38]]

헤드라인 1문장, 도메인 상태(생산·판매·재고) 각 1~2문장, 워치리스트 카드별 요약을 생성한다. 문장마다 각주 번호가 붙고 각주는 근거 행(사건, 기사, 지표값)으로 이어진다.

- [ ] 각주 없는 주장 문장이 0건이다
- [ ] 각주 번호를 누르면 근거 원문(기사 제목·출처·URL 또는 지표값·기준일)이 열린다

#### R16 상관관계까지만 서술

근거: [[TBL-RFQ-001#Q42]] [[TBL-RFQ-001#Q35]]

근거에 없는 인과관계를 단정하지 않는다. 헤드라인에 "상관관계 확인 · 인과관계 미확정" 배지를 붙인다. 발주자 예시 문구의 "물동량 XX% 감소가 예상됩니다"류 예측 표현은 1차에서 쓰지 않는다.

- [ ] 생성문에 예측·단정 어휘 금지 목록이 적용되고 위반 시 재생성 또는 강등된다

#### R17 강조 표시 계약

근거: [[TBL-RFQ-001#Q34]]

LLM은 강조할 키워드와 근거 구절을 마크업 토큰으로만 표시하고, 볼드와 노란 음영 렌더는 화면이 결정적으로 한다. LLM이 HTML이나 스타일을 쓰지 않는다.

- [ ] 강조 토큰 외의 마크업이 생성문에 있으면 제거된다
- [ ] 강조 대상은 문장당 3개 이하로 제한된다

#### R18 이상징후 알림 이벤트

근거: [[TBL-RFQ-001#Q39]]

배치 후 워치리스트가 바뀌면(신규 국가, 신호등 상승) 알림 이벤트를 만든다. 발송 채널은 미결이므로 1차는 이벤트 기록과 화면 배지까지다.

- [ ] 워치리스트 변화가 이벤트 테이블에 남는다
- [ ] 채널 어댑터 없이도 이벤트 생성이 실패하지 않는다

### 3.4 화면

#### R19 레이아웃 순서와 접기

근거: [[TBL-RFQ-001#Q32]] [[TBL-RFQ-001#Q33]]

위에서부터 시장지표 바, AI 요약 헤드라인, 도메인 상태 3카드, 조기경보 워치리스트 순이다. 도메인 상태 카드는 접고 펼 수 있고 기본은 펼침이다.

- [ ] 접힘 상태는 사용자 브라우저에 기억된다

#### R20 워치리스트 카드와 근거 펼치기

근거: [[TBL-RFQ-001#Q37]] [[TBL-RFQ-001#Q38]]

카드마다 국가, 신호등, CBU 비중, 관련 법인 태그, 정형 신호, 비정형 신호, 요약 문장을 보여준다. 근거는 카드 안에서 접었다 펼치며 뉴스 토막(제목·출처·게시일)과 시장 데이터 원값을 보여주고, 기사 URL로 이동할 수 있다.

- [ ] 근거 펼치기에 사건별 기사 3건 이상과 지표 원값이 나온다
- [ ] 폐쇄망에서 외부 URL은 새 창 링크로만 제공하고 화면이 외부 자원을 불러오지 않는다

#### R21 시장지표 바

근거: [[TBL-RFQ-001#Q51]]

- [ ] 4종 지표의 기준일이 데이터 최신일과 일치한다

#### R22 판매 상세 화면

근거: [[TBL-RFQ-001#Q31]] [[TBL-RFQ-001#Q36]]

워치리스트 카드에서 "상세 인사이트 보기"로 들어가는 두 번째 화면이다. 국가별 당월 실적과 비교 기간 대비 표, AI 브리핑 문단, 근거 칩, 시장 데이터 원값을 보여준다. 화면 2본 중 나머지 1본을 이것으로 둔다는 가정이며 미결이다.

- [ ] 카드에서 상세로 이동하고 브라우저 뒤로가기로 돌아온다
- [ ] 상세의 수치가 결합 테이블 값과 일치한다

### 6.1 ML(학습 모델)은 1차에 쓰지 않는다

상태: 제안

| 선택지 | 내용 |
|:--|:--|
| A. 규칙·통계 기반 판정 + LLM 문장 | 임계값과 비율 계산으로 이상·노출·워치리스트를 판정한다. 학습 없음 |
| B. 시계열 이상탐지 모델(국가별 도매 실적 예측 후 잔차로 이상 판정) | 국가 179 × 모델코드 단위 시계열 학습 |
| C. 예측 모델(뉴스·시장 → 물동량 영향 예측) | 자사 연구원 제안서의 24시간~30일 전망. 사건 → 결과 라벨 필요 |

결정: A. B와 C는 2차 사업으로 미룬다.

근거

- 학습 데이터가 없다. 완성차 실적은 3개월치(생산 45,172행, 판매·재고 56,896행)이고 일 단위로 보면 국가당 약 70개 관측점이다. 계절성(연 주기)을 배우려면 최소 2년치가 필요하다. 뉴스는 가공본 이틀, 원본 18일이다. 사건과 결과(물동량 변화)를 잇는 라벨은 0건이다
- 예측 대상 지표가 IF에 없다. 제안서의 예측 목표(리드타임, 운송비, 지연률)는 글로비스 운영 데이터(TMS, GLAPS)에 있고 1차 연계 범위 밖이다
- 발주자가 요구하지 않았다. 과업지시와 기본계획 어디에도 예측 정확도 요구가 없고, 시안의 "인과관계 미확정" 배지를 발주자가 그대로 받았다
- 운영 주체가 없다. 폐쇄망 안에서 재학습, 드리프트 감시, 모델 교체를 할 인력이 발주자 데이터서비스팀에 있는지 확인되지 않았다. 규칙 기반은 임계값 설정으로 현업이 직접 조정할 수 있다
- 검증이 불가능하다. 예측 모델은 "뉴스가 실제로 예측 가치를 더하는가"를 A/B/C 실험(완성차만, +시장, +뉴스)으로 증명해야 하는데 비교할 과거 구간이 없다

A를 택했을 때 필요한 것

- 판정 로직: pandas 수준의 집계와 비율 계산. 추가 패키지 없음
- 임계값 4종을 설정 테이블로 두고 변경 이력을 남긴다 ([[#R11]])
- 판정 근거를 전부 저장해 나중에 라벨링 재료로 쓴다 ([[#R7]] 결합 테이블)

B 또는 C로 갈 때 필요한 자원 (재검토 시 기준)

- 데이터: 결합 테이블 12개월 이상(179개국 × 365일 ≈ 65,000행), 사건 → 결과 라벨(현업이 워치리스트 항목마다 "실제 영향 있었음/없었음"을 기록한 것) 수백 건, 예측 대상 지표의 운영 데이터 연계
- 학습·추론: 표 형식 GBM(LightGBM 등) 기준 CPU 학습 수 분, 배치 추론 수 초. GPU 불필요. 폐쇄망에 파이썬 패키지 반입 절차 필요
- 운영: 월 1회 재학습 배치, 예측 대 실적 오차 감시, 모델 버전 관리, 성능 저하 시 규칙 기반으로 자동 강등. 담당 인력 1명(발주자 측 또는 유지보수 계약)
- 검증: A/B/C 실험 설계와 최소 3개월 백테스트 구간

재검토 조건: 결합 테이블 12개월 축적 + 현업 라벨 300건 이상 + 발주자가 예측 지표(물동량, 선복 수요 등)를 요구로 명시. 셋 다 충족될 때 2차 과업으로 제안한다.

### 6.2 LLM은 두 지점에만 쓴다

상태: 제안

| 지점 | 입력 | 출력 | 실패 시 |
|:--|:--|:--|:--|
| 1. 사건 통합 ([[#R4]]) | 규칙으로 묶인 기사 그룹의 제목·요약 상위 5건 | 사건 제목, 유형, 세부유형, 심각도 | 대표 기사 제목, 카테고리를 유형으로 사용 |
| 2. 문장 생성 ([[#R14]]) | 판정 구조체(2KB 이하) | 헤드라인, 도메인 상태, 카드 요약 (각주·강조 토큰 포함) | 템플릿 문장 |

결정: 위 두 지점 외에 LLM 호출을 두지 않는다. 판정, 랭킹, 매핑, 수치 계산에 LLM을 쓰지 않는다.

근거

- 추적성. 발주자 요구의 핵심이 각주와 근거 링크([[TBL-RFQ-001#Q38]])다. LLM이 수치를 고르면 어느 행에서 나온 문장인지 보장할 수 없다
- 재현성. 같은 날짜를 다시 돌려 같은 판정이 나와야 한다. LLM 판정은 비결정적이다
- 비용 상한. 컨텍스트 105만 토큰이라고 원본 테이블을 넣는 유혹이 생기지만, 넣는 순간 배지와 각주 계약이 깨진다

물량 추정 (원본 18일치 실측 기준: 고유 기사 101,151건, 일 약 5,600건)

| 항목 | 일 호출 수 | 호출당 토큰(입력+출력) | 일 토큰 |
|:--|:--|:--|:--|
| 사건 통합 | 신규·변경 그룹 200~400 | 약 1,350 | 27만~54만 |
| 문장 생성 | 헤드라인 1 + 도메인 3 + 카드 30 + 상세 30 | 약 950 | 약 6만 |
| 합계 | | | 약 35만~60만 |

월 약 1,000만~1,800만 토큰. 기본계획 비용표에 H-chat 사용료 5,000천원이 잡혀 있다. H-chat 단가는 미확인이라 예산 충족 여부는 미결이다. 호출은 동시성 4로 제한하면 사건 통합 400건이 약 5분이며 배치 창 4시간 안에 든다.

필요한 것: 호출별 토큰과 소요 시간을 배치 이력에 기록한다. JSON 모드 기본, 실패 시 복구·강등 ([[#N2]]).

재검토 조건: 일 토큰이 100만을 넘거나 H-chat 단가 확인 결과 월 예산을 초과하면 사건 통합의 LLM 호출을 "심각도 상위 그룹만"으로 줄인다.

### 6.3 사건 통합은 규칙으로 묶고 LLM은 이름만 붙인다

상태: 제안

| 선택지 | 내용 | 탈락 이유 |
|:--|:--|:--|
| A. 규칙(국가 + 카테고리 + 7일 창) + LLM 명명 | 결정적 묶음. LLM은 제목·유형만 | 선택 |
| B. 임베딩 클러스터링 | 기사 벡터로 군집 | 폐쇄망 임베딩 모델 반입 경로 미확정. 하루 수백 건 규모에서 군집이 불안정. 왜 묶였는지 설명 불가 |
| C. LLM이 기사 전량 판독 후 사건 배정 | 기사마다 LLM 호출 | 일 5,600건 × 1,500토큰 = 840만 토큰. 비결정적 |

근거: 발주자 뉴스 API가 이미 카테고리와 국가 태그를 붙여 준다([[TBL-RFQ-001#Q50]]). 이 태그를 믿고 묶으면 규칙만으로 충분히 좁혀지고, LLM은 "이 묶음이 무엇인가"만 답하면 된다. 크로스워크 07 시트의 자체 경고(영향도 합계는 언급빈도에 비례)가 이 결정의 이유다.

알려진 한계: 해협·항로 단위 이슈(호르무즈)가 국가 태그로 잘 안 내려온다. 1차는 사건 위치에 "해협·항로" 값을 허용하고, 크로스워크에 해협 → 인접 국가 표를 추가해 대응한다(미결).

재검토 조건: 사건 압축률이 목표에 못 미치거나(같은 이슈가 국가별로 쪼개짐) 현업이 "다른 사건이 하나로 묶였다"는 지적을 월 5건 이상 하면 B를 검토한다.

### 6.4 이상탐지 기준은 전년동월 대비, 없으면 전월 대비 강등

상태: 제안

| 선택지 | 내용 | 판단 |
|:--|:--|:--|
| A. 전년동월 대비 임계값 | 발주자 원칙([[TBL-RFQ-001#Q52]]). DBA 초안 -50% | 기본 |
| B. 전월 대비 임계값 | 과거 데이터 없을 때 대안 | 강등 경로 |
| C. 이동평균 대비 편차(z-score) | 통계적 이상. 계절성 무시 | 보조 지표로만 기록, 판정에는 미사용 |
| D. 사업계획 대비 | 계획 데이터가 내년에나 연계 ([[TBL-RFQ-001#Q44]]) | 2차 |

결정: A를 원칙으로, 비교 기간이 없으면 B로 강등하고 화면에 기준 방식을 표시한다. C는 결합 테이블에 값만 남긴다.

근거: 발주자가 기존 대시보드에서 "사업계획이 없으므로 전년 동기 대비"를 지시했다. 인텔리전스만 다른 기준을 쓰면 같은 국가의 판정이 화면마다 달라진다. 3개월치로는 A가 불가능하므로 B가 없으면 1차 시연이 안 된다.

필요한 것: 과거 2년치 초기 적재 요청(미결). 들어오면 B 강등이 자연히 사라진다.

재검토 조건: 사업계획 데이터가 연계되면 D를 추가하고 현업과 우선순위를 정한다.

### 6.5 근거 검색은 구조화 조회, 벡터 RAG는 두지 않는다

상태: 제안

기본계획 슬라이드 10에 "전용 RAG 구성: LLM 응답품질 최적화"가 있다. 이 문서에서 RAG의 의미를 "LLM이 근거 안에서만 답하게 하는 구성"으로 해석하고, 구현은 벡터 검색이 아니라 구조화 조회로 한다.

| 선택지 | 내용 | 판단 |
|:--|:--|:--|
| A. 구조화 조회 | 국가·카테고리·기간·심각도로 사건·기사·지표를 SQL로 뽑아 LLM 입력에 넣는다 | 선택 |
| B. 벡터 검색 RAG | 기사 임베딩 색인, 질의 유사도 검색 | 탈락 |

근거: 질의가 자유 문장이 아니라 판정 코드가 만든 구조체다. 어떤 근거를 넣을지는 라우팅 표(크로스워크 08)와 판정 결과가 정하므로 유사도 검색이 필요 없다. 벡터 색인은 폐쇄망 임베딩 경로, OpenSearch 같은 추가 컨테이너, 색인 운영을 요구한다. 브리핑 갈래에서 OpenSearch를 제외한 결정과도 일관된다.

필요한 것: 사건·기사·지표 테이블의 국가·카테고리·일자 인덱스.

재검토 조건: 대화형 질의가 범위에 들어오면(2차) 그때 B를 검토한다.

### 6.6 외부 데이터는 전부 적재하고 판정은 우리 DB에서 한다

상태: 확정 (2026-09-15, 유저가 A 방식 채택. docs/context/decisions.md 2026-09-14 기록과 동일)

| 선택지 | 내용 | 판단 |
|:--|:--|:--|
| A. 전부 적재 | 완성차·뉴스·블룸버그·Marklines를 우리 postgres에 넣고 판정 | 선택 |
| B. 원천 실시간 조회 | 배치 때 발주자 DB·API를 직접 읽음 | 탈락 |

근거: 갱신 주기가 제각각이다(완성차 일별, 뉴스 수시, 블룸버그 일별, Marklines 월별·1~2개월 지연). 과거 시점 재현([[#R13]])은 우리가 스냅샷을 갖고 있어야 가능하다. 매핑 오류(57~94%)는 우리 테이블에서 고쳐야 고칠 대상이 있다. 원천 단절 시 화면이 멈추면 안 된다.

필요한 것: postgres 용량. 뉴스 원본 18일치 320MB 기준 연 약 6.5GB, 결합 테이블 연 65,000행. 3컨테이너 형상 안에서 감당된다.

### 6.7 결합 단위는 국가 × 일자

상태: 확정 (2026-09-15, 유저가 A 방식 채택)

| 선택지 | 판단 |
|:--|:--|
| 국가 × 일자 | 선택. 완성차 기준일자가 일 단위, 블룸버그가 일 단위, 뉴스 게시일이 일 단위. 판매 데이터의 최소 지역 단위가 국가(대리점 앞 3자리) |
| 국가 × 주 | 탈락. 뉴스 급증 같은 일 단위 신호가 묻힌다 |
| 법인 × 일자 | 탈락. 글로비스 법인 매핑이 없다([[#R12]] 미결). 국가 → 법인은 매핑이 오면 위에 얹는다 |
| 국가 × 모델코드 × 일자 | 탈락. 워치리스트는 국가 단위다. 차종 상세는 판정 결과의 부속 정보로 둔다 |

근거: 판정이 단순해지고, 자사 연구원 제안서의 "학습 테이블" 형태와 같아 1년치가 쌓이면 6.1 재검토의 데이터가 된다.

### 6.8 워치리스트는 정형과 비정형이 교차 확인된 국가만

상태: 제안

| 선택지 | 판단 |
|:--|:--|
| 교차 확인(정형 이상 AND 사건) | 선택. DBA 파이프라인과 발주자 메모([[TBL-RFQ-001#Q35]]) 그대로 |
| 정형 이상만 | 탈락. 이유 없는 경보. 도메인 상태 카드에서 보여준다 |
| 비정형 급증만 | 탈락. 언급빈도 순위가 된다(미국·이란 상위 편향) |

근거: 발주자가 워치리스트를 "정형 흐름과 비정형 관련도가 높은 리스트"로 정의했다. 교차 확인은 그 정의의 직역이다.

부작용: 뉴스가 없는 날은 워치리스트가 비어 있을 수 있다. 화면은 "교차 확인된 국가 없음"을 정상 상태로 표시한다.

### 6.9 뉴스 수집과 1차 분류는 발주자 시스템, 우리는 결과를 받는다

상태: 제안

받은 뉴스 데이터에는 이미 카테고리(llm_bk_code), 국가 태그, 영향도 점수, 요약, 분류 사유가 붙어 있다. 발주자 쪽 뉴스 API 파이프라인이 만든 것이다.

결정: 우리는 이 결과를 정본으로 받아 적재한다([[#R3]]). 기사를 다시 분류하거나 점수를 다시 매기지 않는다. 수집 주기와 전달 방식(파일, DB 연결, API)은 미결이다.

근거: 같은 기사를 두 시스템이 다르게 분류하면 어느 쪽이 맞는지 다툼이 생긴다. 발주자 시스템의 분류가 크로스워크 01·08의 전제다.

필요한 것: 원본 published_at_kst 훼손과 가공본·원본 스키마 차이를 발주자에게 회신하고 정본 스키마를 확정한다(미결).

### 6.10 브리핑은 배치로만 만든다, 사용자 새로고침은 없다

상태: 제안

| 선택지 | 판단 |
|:--|:--|
| 새벽 배치 1회 + 개발자 수동 재실행 | 선택 |
| 사용자 새로고침 버튼(즉시 재생성) | 1차 탈락 |

근거: 데이터가 하루 한 번 바뀐다(완성차 일별, 블룸버그 일별). 사용자가 새로고침해도 같은 결과가 나온다. 브리핑 갈래의 새로고침은 대시보드 데이터가 수시로 바뀌는 전제였다. 즉시 생성은 사건 통합 수 분 + LLM 호출이라 화면 대기가 길고, 폴링 구조를 하나 더 만들어야 한다.

재검토 조건: 뉴스가 일 중 여러 번 들어오는 상시 피드가 생기면 "당일 사건만 재통합"하는 부분 재실행을 검토한다.

## 7. 미결사항

답이 오기 전에는 "가정"으로 진행한다. 가정이 뒤집히면 해당 항목을 참조하는 하류만 개정한다.

- [ ] 글로비스 법인 매핑 테이블 수령. 가정: 없음, "법인 미매핑" 표시 ([[#R12]])
- [ ] 완성차 과거 2년치 적재. 가정: 안 됨, 전월 대비로 강등 ([[#R8]], 6.4)
- [ ] 판매 IF에 CBU/CKD 추가. 가정: 안 됨, 생산 모델코드로 유도 ([[#R10]])
- [ ] 워치리스트 국가 수 3 → 10. 가정: 임계값이 정하는 대로, 개수 제한 없음 ([[#R11]])
- [ ] 임계값 4종의 현업 검토. 가정: DBA 초안값 ([[#R11]])
- [ ] 이상징후 알림 채널과 수신자. 가정: 이벤트 기록만 ([[#R18]])
- [ ] 두 번째 화면의 정체. 가정: 판매 상세 ([[#R22]])
- [ ] 뉴스 상시 수집 경로와 정본 스키마. 가정: 가공본 스키마, 파일 업로드 ([[#R3]], 6.9)
- [ ] 블룸버그·뉴스·Marklines 라이선스 범위. 가정: 화면에 원값·제목·링크 표시 가능, 본문 전문은 비노출 ([[#R20]])
- [ ] Marklines 실데이터 인입 시점. 가정: 1차 브리핑에 미사용 ([[#R6]])
- [ ] 완성차 자동 연계 시점. 가정: 파일 업로드 ([[#R1]])
- [ ] 예측형 문구 허용 여부. 발주자 예시는 "예상됩니다"인데 시안 배지는 "인과관계 미확정"이다. 가정: 상관관계까지만 ([[#R16]])
- [ ] 사건 통합 시간창 기본값. 가정: 7일 ([[#R4]], 6.3)
- [ ] H-chat 단가. 6.2의 월 1,000만~1,800만 토큰이 예산 5,000천원 안에 드는지. 가정: 든다
- [ ] 해협·항로 → 인접 국가 매핑표. 가정: 호르무즈, 홍해, 수에즈 3건을 우리가 초안 작성 후 DBA 검토 (6.3)
- [ ] 집계 정의(플로우 합, 스톡 말값, 누적, 전년동월)를 과업 2 태블로 대시보드 팀과 통일. 발주자 확인 요청 항목
- [ ] 6.1~6.5, 6.8~6.10 결정의 유저 승인 (6.6·6.7은 확정)
