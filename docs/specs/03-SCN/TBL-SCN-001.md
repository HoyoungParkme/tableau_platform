# 사용자 시나리오

## 0. 범위와 전제

A 방식(단일 데이터마트, 코드 판정, LLM 두 지점)을 전제로 한다. 화면은 VODA 안의 단독 주소 1본 + 판매 상세 1본. 데이터는 하루 1회 새벽 배치로 갱신되고 사용자는 읽기만 한다. 관리 작업(파일 적재, 매핑 보정, 임계값 조정)은 개발자와 자사 DBA가 한다. 발주자 데이터는 현재 샘플이며 시나리오의 수치는 예시다.

## 1. 페르소나

#### P1 해외운송 담당자 (현업)

역할: 글로비스 해외운송·선복 배정을 맡는 현업 담당자. 아침에 VODA에서 완성차 실적 대시보드를 본다. 비개발자다.
겪는 문제: 국가별 판매 급감이나 재고 체류를 대시보드에서 직접 찾아야 하고, 그 원인이 되는 뉴스나 시장 지표는 따로 검색해야 한다. 어느 국가를 먼저 봐야 하는지 매일 판단해야 한다.
원하는 것: 화면을 열자마자 오늘 볼 국가와 이유가 한눈에 보이고, 근거 기사와 지표 원값을 바로 펼쳐 볼 수 있는 것. 근거: [[TBL-RFQ-001#Q2]] [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q38]]

#### P2 운영 개발자

역할: 인텔리전스 시스템을 만들고 폐쇄망에 반입한 뒤 운영하는 개발자. 완성차·뉴스·블룸버그 파일을 받아 적재하고 배치를 감시한다.
겪는 문제: 데이터가 수작업 파일로 들어오고 스키마가 둘씩 있다. 매핑이 빠진 값이 계속 나온다. 배치가 실패하면 어느 층에서 왜 실패했는지 알아야 한다.
원하는 것: 적재 결과(행수, 결측, 매칭률)가 숫자로 보이고, 실패 지점부터 재실행할 수 있고, 임계값을 코드 수정 없이 바꿀 수 있는 것. 근거: [[TBL-PRD-001#R1]] [[TBL-PRD-001#R24]] [[TBL-PRD-001#N8]]

#### P3 자사 DBA (매핑 관리자)

역할: 크로스워크 테이블을 만들고 유지하는 자사 DBA. 국가·공장·카테고리 매핑과 판정 로직 초안의 주인이다.
겪는 문제: 샘플에서 본 값만 매핑돼 있어 새 공장·국가가 나올 때마다 보강해야 한다. 매핑을 고치면 어느 판정이 바뀌는지 알 수 없다.
원하는 것: 미매핑 값 목록을 받아 엑셀로 보강해 올리면 다음 배치부터 반영되고, 바뀐 국가가 표시되는 것. 근거: [[TBL-PRD-001#R2]] [[TBL-RFQ-001#Q48]]

## 2. 시나리오

### 2.1 열람

#### S1 아침 브리핑 열람

**주체**: P1
**상황**: 출근 후 VODA에서 인텔리전스 버튼을 눌러 단독 주소 화면을 연다. 새벽 배치는 이미 끝나 있다.

1. 화면 상단에 시장지표 바(GPR, Brent, BDI, SCFI)와 기준일이 보인다.
2. AI 요약 헤드라인 한 문장과 "상관관계 확인 · 인과관계 미확정" 배지를 읽는다.
3. 도메인 상태 3카드(생산·판매·재고)의 신호등과 한두 문장을 훑는다. 핵심 키워드는 볼드와 노란 음영으로 강조돼 있다.
4. 조기경보 워치리스트에서 신호등 순으로 정렬된 국가 카드를 본다.
5. 필요한 카드만 남기고 도메인 상태 영역을 접는다.

**변형 — 워치리스트가 비어 있음**: 교차 확인된 국가가 없으면 "오늘 교차 확인된 국가 없음"이 정상 상태로 표시된다. 도메인 상태는 그대로 보인다.
**변형 — 강등 브리핑**: 새벽 LLM 생성이 실패했으면 문장 대신 판정값과 템플릿 문장이 보이고 "요약 생성 실패, 판정값만 표시" 안내가 뜬다.
**변형 — 배치 실패**: 어젯밤 배치가 실패했으면 마지막 성공 브리핑이 기준일과 함께 보인다.

**성공 조건**: 열람 지연 2초 이내, 화면이 LLM을 호출하지 않는다, 발주자 메모의 레이아웃 순서와 같다.
**연관 요구사항**: [[TBL-PRD-001#R19]] [[TBL-PRD-001#R21]] [[TBL-PRD-001#R15]] [[TBL-PRD-001#N2]] [[TBL-PRD-001#N5]]

#### S2 워치리스트 근거 확인

**주체**: P1
**상황**: 오만 카드가 RED로 떠 있다. 왜 그런지 확인하려 한다.

1. 카드에서 정형 신호(판매 전년동월 대비 -100%, 기준 방식 표시), 비정형 신호(호르무즈 관련 사건 1건, 기사 8건), CBU 비중, 관련 법인 태그를 읽는다.
2. "근거 펼치기"를 누른다.
3. 사건 제목, 기사 3건(제목, 출처, 게시일), 시장 지표 원값(GPR, Brent, BDI, SCFI 변화율)이 펼쳐진다.
4. 기사 제목을 누르면 새 창으로 원문 URL이 열린다.
5. 요약 문장의 각주 번호를 누르면 어느 근거에서 나온 문장인지 표시된다.

**변형 — 법인 미매핑**: 관련 법인 태그가 "법인 미매핑"으로 보인다. 오류가 아니라 매핑 데이터가 없다는 뜻이다.
**변형 — 노출 미확인**: CBU/CKD 유도가 안 된 국가는 "노출 미확인"이 보이고 신호등은 YELLOW 이하다.

**성공 조건**: 각주 없는 문장이 없다. 근거 펼치기에 기사 3건 이상과 지표 원값이 나온다. 화면이 외부 자원을 불러오지 않는다.
**연관 요구사항**: [[TBL-PRD-001#R20]] [[TBL-PRD-001#R15]] [[TBL-PRD-001#R12]] [[TBL-PRD-001#R10]]

#### S3 판매 상세 보기

**주체**: P1
**상황**: 오만 카드의 "상세 인사이트 보기"를 누른다.

1. 판매 상세 화면으로 이동한다. 국가 필터에 오만이 선택돼 있다.
2. 국가별 당월 실적과 비교 기간 대비 표(기준 방식 명시)를 본다.
3. AI 브리핑 문단과 근거 칩(판매진도, 기사, 블룸버그 시계열, 차종 노출)을 읽는다.
4. 근거 상세 펼치기에서 시장 데이터 원값을 본다.
5. 브라우저 뒤로가기로 워치리스트로 돌아온다.

**변형 — 비교 기간 없음**: 전년동월 데이터가 없으면 전월 대비로 표시되고 "계획·전년 데이터 미제공으로 전월 대비 기준"이 표에 붙는다.

**성공 조건**: 상세의 수치가 결합 테이블 값과 일치한다. 뒤로가기가 동작한다.
**연관 요구사항**: [[TBL-PRD-001#R22]] [[TBL-PRD-001#R8]]

### 2.2 배치와 적재

#### S4 새벽 배치 (시스템)

**주체**: 시스템 (P2가 감시)
**상황**: 매일 02:00 배치가 시작된다.

1. 적재: 도착한 파일 5종을 원본 보존하고 스키마 검증, 행수·결측 계수.
2. 표준화: 코드 매핑, 국가 유도, CBU/CKD 유도, 카테고리 정규화. 미매핑은 목록에 쌓는다.
3. 사건 통합: 당일 신규 기사를 국가+카테고리+7일 창으로 묶고 LLM으로 이름 붙인다(LLM 지점 1).
4. 집계·결합: 국가×일 집계, as-of 조인, 비교값 계산으로 signal_daily를 만든다.
5. 판정: 임계, 노출, 교차 확인, 신호등, 법인 태그로 judgment·watchlist·domain_status를 만든다.
6. 서술: 판정 구조체(2KB 이하)를 LLM에 보내 문장과 각주 토큰을 받는다(LLM 지점 2).
7. 검증·게시: 숫자·날짜 대조, 금지어 검사. 통과하면 게시하고 워치리스트 변화 이벤트를 남긴다.

**변형 — 3단계 LLM 실패**: 규칙 묶음만으로 사건을 만들고 제목은 대표 기사 제목으로 대체한다. 배치는 계속된다.
**변형 — 6단계 LLM 실패 또는 검증 실패**: 템플릿 문장으로 강등해 게시하고 사유를 기록한다.
**변형 — 1~5단계 실패**: 배치를 멈추고 실패 단계와 사유를 이력에 남긴다. 화면은 이전 브리핑을 유지한다.
**변형 — 회귀 검사 급변**: 행수·매칭률·중복률이 이전 배치 대비 급변하면 배치를 멈추고 P2에게 알린다.

**성공 조건**: 4시간 창 안에 끝난다. 단계별 소요와 처리 건수가 이력에 남는다. 같은 기준일로 다시 돌리면 판정이 같다.
**연관 요구사항**: [[TBL-PRD-001#R24]] [[TBL-PRD-001#R4]] [[TBL-PRD-001#R7]] [[TBL-PRD-001#R11]] [[TBL-PRD-001#R14]] [[TBL-PRD-001#N2]] [[TBL-PRD-001#N3]] [[TBL-PRD-001#N6]]

#### S5 완성차 파일 수신과 적재

**주체**: P2
**상황**: 발주자가 완성차 데이터 엑셀(생산·판매재고)을 메일로 보냈다. 자동 연계는 아직 없다.

1. 관리 화면에서 소스 "완성차 생산"을 고르고 파일을 올린다.
2. 시스템이 IF 레이아웃(17열) 대조, 기준일자 범위, 행수, 결측, 미래 골격 행을 검사해 보여준다.
3. P2가 확인하고 적재를 실행한다. 같은 기준일자가 이미 있으면 덮어쓰기임을 안내한다.
4. 적재 결과(행수 일치, 결측률, 매칭률, 중복 의심 일자)가 이력에 남고 화면에 보인다.
5. 필요하면 해당 기준일 범위만 배치를 재실행한다.

**변형 — 레이아웃 불일치**: 컬럼이 다르면 적재를 막고 어느 컬럼이 다른지 보여준다. 스키마 버전을 추가해야 한다.
**변형 — 백필**: 과거 2년치가 오면 백필 모드로 올린다. 판정은 돌리되 LLM 명명·서술은 생략하고 결합 테이블만 채운다.

**성공 조건**: 적재 후 행수가 원본과 일치한다. 원본 파일이 보존된다.
**연관 요구사항**: [[TBL-PRD-001#R1]] [[TBL-PRD-001#N7]] [[TBL-PRD-001#N8]]

#### S6 뉴스·블룸버그·Marklines 수신

**주체**: P2
**상황**: 뉴스 CSV(가공본 또는 원본), 블룸버그 엑셀 4종, Marklines CSV가 들어왔다.

1. 소스별로 파일을 올린다. 뉴스는 스키마 버전(가공본/원본)을 자동 판별한다.
2. 뉴스는 result_id로 중복 제거, 국가 다중 태그 분해, 카테고리 정규화(FWD/KD 결합, FVL 배정)를 거친다.
3. 블룸버그는 시계열 시트만 market_series로 들어가고 재무 시트는 원본 보존만 한다.
4. Marklines는 기준월과 인입일을 함께 저장한다.
5. 결과(건수, 기간, 미매핑 국가, 훼손 시각 건수)가 이력에 남는다.

**변형 — 게시 시각 훼손**: 원본의 published_at_kst가 깨진 행은 published_date_kst로 대체하고 정밀도 플래그를 남긴다.

**성공 조건**: 가공본과 원본이 같은 테이블에 들어가고 중복이 없다. 시장지표 4종의 최신값이 조회된다.
**연관 요구사항**: [[TBL-PRD-001#R3]] [[TBL-PRD-001#R5]] [[TBL-PRD-001#R6]]

#### S7 특정 일자 재생성

**주체**: P2
**상황**: 발주자가 "9월 8일 브리핑을 다시 확인해 달라"고 했다. 그 사이 매핑이 바뀌었다.

1. 관리 화면에서 기준일 2026-09-08을 지정해 재생성을 요청한다.
2. 시스템은 그날의 데이터 스냅샷과 그날 사용한 임계값으로 판정을 다시 돌린다.
3. 결과가 당시 판정과 같은지 비교해 보여준다. 다르면 어느 입력(매핑, 임계값, 늦게 온 데이터)이 달라졌는지 표시한다.
4. 새 버전으로 저장할지 P2가 정한다. 기존 브리핑은 덮어쓰지 않는다.

**성공 조건**: 같은 입력이면 필드 단위로 같은 판정이 나온다. 브리핑 버전이 남는다.
**연관 요구사항**: [[TBL-PRD-001#R13]] [[TBL-PRD-001#N3]]

### 2.3 운영

#### S8 미매핑 값 보강

**주체**: P3
**상황**: 적재 이력에 "생산공장 미매핑 30건"이 떠 있다.

1. P3가 미매핑 목록(값, 등장 횟수, 첫 등장일)을 내려받는다.
2. 크로스워크 03 시트에 기아 공장 30종을 추가해 엑셀을 올린다.
3. 시스템이 매핑 차이(추가 30, 변경 0, 삭제 0)와 영향 받는 국가를 보여준다.
4. P3가 확인하면 마스터가 갱신되고 다음 배치부터 반영된다. 과거 판정은 바뀌지 않는다.

**변형 — 과거 재계산 요청**: P2가 특정 기간 재계산을 별도로 실행하면 새 버전으로 만들어진다([[#S7]]).

**성공 조건**: 다음 배치의 생산→국가 매칭률이 올라간다(39/69에서 상승). 매핑 변경 이력이 남는다.
**연관 요구사항**: [[TBL-PRD-001#R2]] [[TBL-PRD-001#N8]]

#### S9 임계값 조정

**주체**: P2 (현업 P1의 검토 결과를 받아)
**상황**: 실데이터 1개월 축적 후 현업 검토에서 "전년대비 -50%는 너무 느슨하다, -30%로"라는 의견이 나왔다.

1. P2가 설정 화면에서 YOY_ANOMALY_THRESHOLD를 -0.5에서 -0.3으로 바꾸고 사유를 적는다.
2. 시스템이 변경 이력을 남기고 "다음 배치부터 적용"을 안내한다.
3. 다음 배치의 judgment 행에 사용 임계값 -0.3이 저장된다.
4. 이전 브리핑은 -0.5 기준 그대로 남는다.

**성공 조건**: 코드 수정 없이 바뀐다. 과거 판정의 재현성이 유지된다.
**연관 요구사항**: [[TBL-PRD-001#R8]] [[TBL-PRD-001#R11]]

#### S10 워치리스트 변화 알림

**주체**: 시스템 → P1
**상황**: 새벽 배치에서 파키스탄이 새로 YELLOW로 올라왔다.

1. 검증·게시 단계에서 어제와 오늘의 워치리스트를 비교한다.
2. 신규 국가, 신호등 상승, 신호등 하강, 이탈을 이벤트로 기록한다.
3. 화면의 워치리스트 카드에 "신규" 또는 "상승" 배지가 붙는다.
4. 발송 채널이 정해지면 어댑터가 이벤트를 읽어 보낸다. 1차는 기록과 배지까지다.

**성공 조건**: 이벤트가 테이블에 남는다. 채널 어댑터 없이도 실패하지 않는다.
