# 사용자 시나리오

## 0. 범위와 전제

리포트 4개([[TBL-RFQ-001#Q54]] [[TBL-RFQ-001#Q55]] [[TBL-RFQ-001#Q58]])를 전제로 하고 이름을 아래로 고정한다(유저 확정 2026-09-16).

| 이름 | 무엇 | 만드는 곳 | 원인을 찾는 곳 |
|:--|:--|:--|:--|
| A1 | 생산 리포트. 생산 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 생산 대시보드 데이터 안 |
| A2 | 재고 리포트. 재고 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 재고 대시보드 데이터 안 |
| A3 | 판매 리포트. 판매 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 판매 대시보드 데이터 안 |
| C | 종합 리포트. 과업지시의 "인텔리전스 서비스 개요" 화면 | 이 문서의 시스템 | 뉴스·블룸버그(외부) + 세 도메인 교차 |

대시보드 3본(생산·재고·판매)은 태블로 팀이 만든다. A 리포트(A1~A3 통칭)는 자기 도메인 데이터만 보고 원인도 그 안에서 찾는다(어느 국가·차종·공장이 변동을 만들었나). C는 A 리포트의 요약이 아니라 별개의 인사이트다. A 판정(A 리포트의 변동 판정값과 내부 분해 결과)을 입력으로 받아 뉴스·시장 데이터에서 외부 원인 후보를 찾고 H-chat이 연관을 판단한 뒤, "생산은 어떻고, 재고는 어떻고, 판매는 어떻고, 외부와 같이 보니 이렇다"를 종합 관점에서 새로 쓴다(PRD G2, R29, 6.11, R15). A 리포트에서 C로 들어가는 화면 흐름은 없다. C는 VODA 단독 주소 1본으로 따로 연다. 데이터는 하루 1회 새벽 배치로 갱신되고 현업은 읽는다. 관리 작업은 개발자와 자사 DBA가 한다. 화면 구성은 고정이 아니며([[TBL-RFQ-001#Q56]]) 시나리오의 수치는 예시다.

시나리오는 네 묶음이다. 2.1 A 리포트, 2.2 C 리포트(인텔리전스 서비스 개요), 2.3 배치와 적재, 2.4 운영.

## 1. 페르소나

#### P1 해외운송 담당자 (현업)

역할: 글로비스 해외운송·선복 배정을 맡는 현업 담당자. 아침에 VODA에서 완성차 생산·재고·판매 대시보드 3본과 각각의 A 리포트, 그리고 C 리포트를 본다. 비개발자다.
겪는 문제: 대시보드와 A 리포트가 "오만 도매가 급감했고 투싼·아반떼가 만들었다"까지는 보여 주지만, 바깥에서 왜 그런지는 뉴스와 시장 지표를 따로 뒤져야 한다. 세 대시보드를 오가며 어느 국가를 먼저 봐야 하는지 매일 판단해야 한다.
원하는 것: C 리포트를 열면 세 도메인의 변동이 한 화면에 모이고, 변동마다 외부 원인 후보와 그 근거가 붙어 있는 것. 근거: [[TBL-RFQ-001#Q2]] [[TBL-RFQ-001#Q35]] [[TBL-RFQ-001#Q38]] [[TBL-RFQ-001#Q55]]

#### P2 운영 개발자

역할: C 시스템을 만들고 폐쇄망에 반입한 뒤 운영하는 개발자. 완성차·뉴스·블룸버그 파일을 적재하고, A 판정 스냅샷 연결을 유지하고, 배치를 감시한다.
겪는 문제: 데이터가 수작업 파일로 들어오고 스키마가 둘씩 있다. 매핑이 빠진 값이 계속 나온다. 배치가 실패하면 어느 단계에서 왜 실패했는지, LLM이 얼마나 쓰였는지 알아야 한다.
원하는 것: 적재 결과가 숫자로 보이고, 실패 지점부터 재실행할 수 있는 것. 근거: [[TBL-PRD-001#R1]] [[TBL-PRD-001#R24]] [[TBL-PRD-001#N8]]

#### P3 자사 DBA (매핑 관리자)

역할: 크로스워크 테이블을 만들고 유지하는 자사 DBA. 국가·공장·카테고리 매핑과 판정 로직 초안의 주인이다.
겪는 문제: 샘플에서 본 값만 매핑돼 있어 새 공장·국가가 나올 때마다 보강해야 한다. 매핑을 고치면 어느 판정이 바뀌는지 알 수 없다.
원하는 것: 미매핑 값 목록을 받아 엑셀로 보강해 올리면 다음 배치부터 반영되고, 바뀐 국가가 표시되는 것. 근거: [[TBL-PRD-001#R2]] [[TBL-RFQ-001#Q48]]

## 2. 시나리오

### 2.1 A 리포트 (A1 생산 · A2 재고 · A3 판매)

대시보드 3본에 각각 붙는 AI 인사이트 리포트다. 자기 도메인 데이터만 보고, 원인도 그 안에서 찾는다. C로 넘어가는 버튼이나 링크는 없다.

#### S13 A 리포트 3개를 본다

**주체**: P1
**상황**: VODA에서 생산·재고·판매 대시보드를 차례로 연다. 대시보드마다 A 리포트가 붙어 있다.

1. A3 판매 리포트는 판매 트래킹 지표(국가·차종별 선적·도매·소매)의 변동과 해설, 차트를 보여 준다.
2. 변동의 원인은 그 대시보드 데이터 안에서 분해해 보여 준다. "도매 전월 대비 -12%는 중동 3개국이 -9%p, 나머지 -3%p"처럼 어느 국가·차종이 변동을 얼마나 만들었는지 기여 상위 항목을 표시한다.
3. A2 재고 리포트는 재고 트래킹 지표(국가별 체류·MOS·장기 재고)의 변동과 그 내부 분해를 보여 준다. A3와 내용이 다르다.
4. A1 생산 리포트는 생산 트래킹 지표(공장·차종별 생산)의 변동과 내부 분해를 보여 준다.
5. 세 리포트 어디에도 뉴스·시장지표는 없다. "왜 중동이 줄었는가"의 외부 원인은 여기서 답하지 않는다.

**변형 — 트래킹 지표 미지정**: 현업 인터뷰 전이면 프로필 핵심지표 전부가 후보이며 개발자가 임시 지정한다(브리핑 갈래 F-034).

**성공 조건**: 세 리포트의 트래킹 지표 목록이 서로 다르다. 변동마다 기여 상위 항목이 표시된다. 외부요인 인용이 0건이다.
**연관 요구사항**: [[TBL-PRD-001#R29]] [[TBL-PRD-001#G1]] [[TBL-PRD-001#G2]]

### 2.2 C 리포트 (종합, 인텔리전스 서비스 개요)

과업지시의 "인텔리전스 서비스 개요" 시트(C3~C12)가 가리키는 화면이다. 외부요인은 이 화면에서만 결합된다. 카드 구성은 디자인 방향일 뿐이라 시나리오는 화면 1본에서 읽고 근거를 펼치는 흐름만 정한다. 국가 상세 화면은 별도 시나리오로 두지 않는다. 필요하면 UI 명세에서 후보로 다룬다.

#### S1 아침 C 리포트 열람

**주체**: P1
**상황**: 출근 후 VODA에서 C 리포트 단독 주소를 연다. 새벽 배치는 끝나 있다.

1. 상단에 시장지표 바(GPR, Brent, BDI, SCFI)와 기준일이 보인다.
2. AI 요약 헤드라인 한 문장과 "상관관계 확인 · 인과관계 미확정" 배지를 읽는다. 헤드라인은 두 도메인 이상 또는 도메인과 외부 원인을 함께 말한다.
3. 도메인 상태 3카드(생산·재고·판매)를 훑는다. 신호등은 A 판정에서 왔지만 문장은 종합 관점에서 새로 쓴 것이다. "판매는 중동 3개국이 급감했고, 같은 국가의 항해중 재고가 늘었으며, 호르무즈 사건과 시점이 겹친다"처럼 다른 도메인과 외부 원인에 비추어 서술된다. 핵심 키워드는 강조돼 있다.
4. 변동 목록(국가별로 묶인 워치리스트)에서 신호등 순으로 정렬된 카드를 본다. 카드마다 변동, 원인 후보, 관련도, 연관 설명이 있다. 변동 수치와 내부 분해는 A 판정과 같다.
5. 원인 후보가 없는 변동은 "원인 미확인"으로 목록 끝에 있다.
6. 필요한 카드만 남기고 도메인 상태 영역을 접는다.

**변형 — 변동이 없음**: 세 도메인 모두 변동이 없으면 "오늘 감지된 변동 없음"이 정상 상태로 표시된다.
**변형 — 강등 리포트**: 연관 판단이나 문장 생성이 실패했으면 후보 목록만 관련도 없이 보이거나 템플릿 문장이 보이고 "생성 실패, 판정값만 표시" 안내가 뜬다.
**변형 — 배치 실패**: 마지막 성공 리포트가 기준일과 함께 보인다.
**변형 — 비교 기간 없음**: 전월 대비로 표시되고 "계획·전년 데이터 미제공으로 전월 대비 기준"이 붙는다.
**변형 — 대시보드에 국가 시트가 없음**: C는 IF 보완 집계로 국가 변동을 만들고 카드에 "보완 집계"임을 표시한다.

**성공 조건**: 열람 지연 2초 이내, LLM 호출 없음, 발주자 메모의 순서. 도메인 상태 문장이 A 리포트 문장과 다르다. 같은 변동의 수치가 A 판정과 일치한다.
**연관 요구사항**: [[TBL-PRD-001#R19]] [[TBL-PRD-001#R21]] [[TBL-PRD-001#R15]] [[TBL-PRD-001#R25]] [[TBL-PRD-001#R23]] [[TBL-PRD-001#R11]] [[TBL-PRD-001#R8]] [[TBL-PRD-001#N2]] [[TBL-PRD-001#N5]]

#### S2 변동의 외부 원인 후보와 근거 확인 (C 리포트)

**주체**: P1
**상황**: C 리포트에서 오만 카드가 RED다. 어떤 외부 후보가 왜 관련 있다고 나왔는지 확인한다. 외부 원인 탐색은 C 리포트에서만 일어난다([[TBL-RFQ-001#Q55]]).

1. 카드에서 변동(도매 전월 대비 -100%, 기준 방식 표시), 노출(CBU 100%), 관련도 높음 후보(호르무즈 해협 사건, 기사 8건), 연관 설명 한 문단을 읽는다.
2. "근거 펼치기"를 누른다.
3. 후보 전부가 관련도 순으로 펼쳐진다. 사건 제목과 기사 3건(제목, 출처, 게시일), 시장 지표 변화(BDI -10.1% 등)와 원값, 같은 국가의 다른 도메인 변동(항해중 재고 418대).
4. 기사 제목을 누르면 새 창으로 원문이 열린다.
5. 연관 설명의 각주 번호를 누르면 어느 후보에서 나온 문장인지 표시된다.

**변형 — 관련도 높음 없음**: "원인 후보 확인 안 됨"이 표시되고 후보는 낮음·무관으로만 펼쳐진다. 신호등 없음.
**변형 — 법인 미매핑**: 관련 법인 자리가 비어 있다. 오류가 아니다.
**변형 — 노출 미확인**: "노출 미확인"이 보이고 신호등은 YELLOW 이하다.

**성공 조건**: 연관 설명의 인용이 전부 후보 안에 있다. 근거 펼치기에 기사 3건 이상과 지표 원값이 나온다.
**연관 요구사항**: [[TBL-PRD-001#R20]] [[TBL-PRD-001#R26]] [[TBL-PRD-001#R27]] [[TBL-PRD-001#R12]] [[TBL-PRD-001#R10]]

### 2.3 배치와 적재

#### S4 C 리포트 새벽 배치 (시스템)

**주체**: 시스템 (P2가 감시)
**상황**: 매일 02:00 배치가 시작된다. A 리포트 배치는 그 전에 끝나 있다.

1. 적재: 도착한 파일을 원본 보존하고 스키마 검증, 행수·결측 계수, 표준화, 미매핑 수집, 회귀 검사.
2. A 판정 읽기: A1·A2·A3의 스냅샷 판정값과 내부 분해 결과를 도메인·국가·일자 키로 가져온다. A 리포트가 쓴 문장은 가져오지 않는다. 국가 시트가 없는 지표는 IF 보완 집계로 채운다.
3. 사건 묶음: 당일 신규 기사를 국가(해협 귀속 포함)+카테고리+7일 창 규칙으로 사건에 붙인다. LLM 없음.
4. 결합: 국가×일 결합 테이블(signal_daily)을 만든다. 변동 목록이 여기서 확정된다.
5. 후보 검색: 변동마다 사건·기사·시장지표·타 도메인 변동 후보를 뽑아 ID와 함께 저장한다.
6. LLM 명명: 후보로 뽑힌 사건에만 제목·유형·심각도를 붙인다(LLM 역할 1).
7. 연관 판단: 변동 사실 + 후보 목록을 H-chat에 보내 관련도·설명·인용 ID를 받는다(LLM 역할 2). 검증기가 인용이 후보 안인지 확인한다.
8. 서술·게시: 헤드라인, 도메인 상태(종합 관점, 다른 도메인과 외부 원인에 비추어), 카드 요약을 생성하고(LLM 역할 3), 숫자·날짜·금지어를 검증한 뒤 게시한다. 워치리스트 변화 이벤트를 남긴다.

**변형 — A 판정 스냅샷이 없음(A 리포트 배치 실패)**: C는 IF 보완 집계만으로 변동을 만들고 리포트에 "대시보드 판정 미수신"을 표시한다.
**변형 — 6·7·8단계 LLM 실패 또는 검증 실패**: 명명은 대표 기사 제목, 연관은 후보 목록만, 서술은 템플릿으로 강등해 게시한다.
**변형 — 1~5단계 실패**: 배치를 멈추고 실패 단계를 이력에 남긴다. 이전 리포트를 유지한다.
**변형 — 회귀 검사 급변**: 자동 배치를 막고 P2에게 알린다.

**성공 조건**: 4시간 창 안에 끝난다. 같은 기준일로 다시 돌리면 변동과 후보가 같다. LLM 호출 수가 후보 사건 수 + 변동 수 + 서술 섹션 수를 넘지 않는다.
**연관 요구사항**: [[TBL-PRD-001#R24]] [[TBL-PRD-001#R25]] [[TBL-PRD-001#R4]] [[TBL-PRD-001#R7]] [[TBL-PRD-001#R26]] [[TBL-PRD-001#R27]] [[TBL-PRD-001#R14]] [[TBL-PRD-001#R15]] [[TBL-PRD-001#N2]] [[TBL-PRD-001#N3]] [[TBL-PRD-001#N6]]

#### S5 완성차 파일 수신과 적재

**주체**: P2
**상황**: 발주자가 완성차 데이터 엑셀(생산·판매재고)을 메일로 보냈다. 자동 연계는 아직 없다.

1. 관리 화면에서 소스 "완성차 생산"을 고르고 파일을 올린다.
2. 시스템이 IF 레이아웃(17열) 대조, 기준일자 범위, 행수, 결측, 미래 골격 행을 검사해 보여준다.
3. P2가 확인하고 적재를 실행한다. 같은 기준일자가 이미 있으면 덮어쓰기임을 안내한다.
4. 적재 결과(행수 일치, 결측률, 매칭률, 중복 의심 일자)가 이력에 남고 화면에 보인다.
5. 필요하면 해당 기준일 범위만 배치를 재실행한다.

**변형 — 레이아웃 불일치**: 컬럼이 다르면 적재를 막고 어느 컬럼이 다른지 보여준다.
**변형 — 백필**: 과거 2년치가 오면 백필 모드로 올린다. 결합 테이블만 채우고 LLM 세 역할은 생략한다.

**성공 조건**: 적재 후 행수가 원본과 일치한다. 원본 파일이 보존된다.
**연관 요구사항**: [[TBL-PRD-001#R1]] [[TBL-PRD-001#N7]] [[TBL-PRD-001#N8]]

#### S6 뉴스·블룸버그·Marklines 수신

**주체**: P2
**상황**: 뉴스 CSV(가공본 또는 원본), 블룸버그 엑셀 4종, Marklines CSV가 들어왔다.

1. 소스별로 파일을 올린다. 뉴스는 스키마 버전(가공본/원본)을 자동 판별한다.
2. 뉴스는 result_id로 중복 제거, 국가 다중 태그 분해, 카테고리 정규화(FWD/KD 결합, FVL 배정)를 거친다.
3. 블룸버그는 시계열 시트만 market_series로 들어가고 재무 시트는 원본 보존만 한다.
4. Marklines는 기준월과 인입일을 함께 저장한다.
5. 결과(건수, 기간, 미매핑 국가, 훼손 시각 건수)가 이력에 남는다.

**변형 — 게시 시각 훼손**: published_at_kst가 깨진 행은 published_date_kst로 대체하고 정밀도 플래그를 남긴다.

**성공 조건**: 가공본과 원본이 같은 테이블에 들어가고 중복이 없다. 시장지표 4종의 최신값이 조회된다.
**연관 요구사항**: [[TBL-PRD-001#R3]] [[TBL-PRD-001#R5]] [[TBL-PRD-001#R6]]

#### S7 특정 일자 재생성

**주체**: P2
**상황**: 발주자가 "8월 20일 리포트를 다시 확인해 달라"고 했다. 그 사이 매핑이 바뀌었다.

1. 관리 화면에서 기준일 2026-08-20을 지정해 재생성을 요청한다.
2. 시스템은 그날의 데이터 스냅샷, 그날 사용한 A 판정, 그날의 설정 버전으로 변동과 후보를 다시 만든다.
3. 변동과 후보가 당시와 같은지 비교해 보여준다. 다르면 어느 입력(매핑, 설정, 늦게 온 데이터, A 판정)이 달라졌는지 표시한다. 연관 판단과 문장은 새로 생성되므로 달라질 수 있다.
4. 새 버전으로 게시할지 P2가 정한다. 기존 리포트는 덮어쓰지 않는다.

**성공 조건**: 같은 입력이면 변동·후보가 필드 단위로 같다. 리포트 버전이 남는다.
**연관 요구사항**: [[TBL-PRD-001#R13]] [[TBL-PRD-001#N3]]

### 2.4 운영

#### S8 미매핑 값 보강

**주체**: P3
**상황**: 적재 이력에 "생산공장 미매핑 30건"이 떠 있다.

1. P3가 미매핑 목록(값, 등장 횟수, 첫 등장일)을 내려받는다.
2. 크로스워크 03 시트에 기아 공장 30종을 추가해 엑셀을 올린다.
3. 시스템이 매핑 차이(추가 30, 변경 0, 삭제 0)와 영향 받는 국가를 보여준다.
4. P3가 확인하면 마스터가 갱신되고 다음 배치부터 반영된다. 과거 판정은 바뀌지 않는다.

**변형 — 과거 재계산 요청**: P2가 특정 기간 재계산을 별도로 실행하면 새 버전으로 만들어진다([[#S7]]).

**성공 조건**: 다음 배치의 생산→국가 매칭률이 올라간다(39/69에서 상승). 매핑 변경 이력이 남는다.
**연관 요구사항**: [[TBL-PRD-001#R2]] [[TBL-PRD-001#N8]]

#### S10 워치리스트 변화 알림

**주체**: 시스템 → P1
**상황**: 새벽 배치에서 파키스탄이 새로 YELLOW로 올라왔다.

1. 게시 단계에서 어제와 오늘의 국가별 신호등을 비교한다.
2. 신규 국가, 신호등 상승, 하강, 이탈을 이벤트로 기록한다.
3. 화면의 카드에 "신규" 또는 "상승" 배지가 붙는다.
4. 발송 채널이 정해지면 어댑터가 이벤트를 읽어 보낸다. 1차는 기록과 배지까지다.

**성공 조건**: 이벤트가 테이블에 남는다. 채널 어댑터 없이도 실패하지 않는다.
**연관 요구사항**: [[TBL-PRD-001#R18]]
