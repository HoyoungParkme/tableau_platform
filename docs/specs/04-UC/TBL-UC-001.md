# USECASE (Cockburn)

## 0. 이 문서의 형식

Cockburn 완전 서술형. 항목 ID는 `UC-{액터코드}{번호}`. 액터코드 H는 현업 사용자, A는 관리자(운영 개발자와 자사 DBA), S는 시스템(배치 스케줄러)이다. 사용자 목표 수준은 한 번의 이용으로 목표가 끝나는 것, 하위기능 수준은 사용자 목표 유스케이스가 포함(include)하는 내부 단계다. 확장은 `3a.` 형식이다.

전제는 [[TBL-SCN-001]] 0절과 같다. 3층 구조, 리포트 4개, 도메인 리포트의 원인은 대시보드 데이터 안에서, 외부 원인 탐색은 종합 리포트에서만. 삭제된 항목 UC-H3(상세 보기), UC-A3(임계값 조정)의 ID는 재사용하지 않는다.

## 2. 사용자 목표 수준 유스케이스

### 2.1 도메인 리포트 (2층)

#### UC-H4 도메인 리포트를 본다

| 항목 | 내용 |
|---|---|
| 범위 | 대시보드 3본에 붙는 AI 인사이트 리포트 |
| 수준 | 사용자 목표 |
| 주 액터 | H |
| 이해관계자와 관심사 | H: 이 도메인에서 무엇이 변했고 어디가 만들었나. 발주자: 도메인마다 다른 인사이트 |
| 사전조건 | 2층 배치가 끝나 대시보드 스냅샷 판정이 있다 |
| 최소 보장 | 트래킹 지표의 변동 판정값이 표시된다 |
| 성공 보장 | 변동마다 내부 분해(기여 상위 항목)가 붙은 리포트가 표시되고 외부요인 인용이 0건이다 |
| 트리거 | H가 VODA에서 생산·판매·재고 대시보드 중 하나를 연다 |
| 패키지 | domain_report (브리핑 갈래) |
| 포함(include) | — |
| 확장점(extension point) | 4. 종합 리포트 진입 → [[#UC-H5]] |
| 일반화 | — |

**기본 흐름**
1. 리포트가 해당 도메인의 트래킹 지표(판매: 국가·차종별 선적·도매·소매 / 재고: 국가별 체류·MOS·장기 재고 / 생산: 공장·차종별 생산)의 변동 판정과 차트를 보여준다.
2. 변동마다 그 대시보드 데이터 안에서의 분해를 보여준다. 어느 국가·차종·공장이 변동을 얼마나 만들었는지 기여 상위 항목이다.
3. 해설 문장은 도메인 안의 사실만 말한다. 뉴스·시장지표를 인용하지 않는다.
4. H가 종합 리포트 버튼을 누르면 [[#UC-H5]]로 간다.

**확장**
- **1a. 트래킹 지표가 아직 지정되지 않았다**
  - 1a1. 프로필 핵심지표 전부를 후보로 쓰고 개발자 임시 지정임을 표시한다(브리핑 갈래 F-034).
- **2a. 분해할 차원이 없다(단일 집계 시트)**
  - 2a1. 변동 판정만 보여주고 "분해 불가"를 표시한다.

**연관**: [[TBL-PRD-001#R29]] · [[TBL-PRD-001#G2]] · [[TBL-SCN-001#S13]]

| 성공 보장 | 같은 변동이 종합 리포트 변동 목록에 있고 수치가 2층과 일치하며 문장은 다르다 |
| 트리거 | H가 종합 리포트 버튼 또는 단독 주소를 연다 |

**기본 흐름**
1. 3층 화면이 열린다([[#UC-H1]]). 추가 로그인이 없다.
2. 2층에서 보던 변동(예: 오만 도매 급감)이 변동 목록에 있다. 수치와 내부 분해는 2층과 같다.
3. 문장은 종합 관점이다. 다른 도메인의 같은 국가 변동과 외부 원인 후보에 비추어 서술된다. 2층 문장이 반복되지 않는다.

**확장**
- **2a. 대시보드에 국가 시트가 없어 2층 판정이 국가 단위가 아니다**
  - 2a1. 3층은 IF 보완 집계로 만든 국가 변동을 보여주고 카드에 "보완 집계"를 표시한다.

### 2.2 인텔리전스 서비스 개요 (3층 종합 리포트)

#### UC-H1 오늘의 종합 리포트를 본다

| 항목 | 내용 |
|---|---|
| 범위 | 종합 리포트 화면 (인텔리전스 서비스 개요) |
| 수준 | 사용자 목표 |
| 주 액터 | H |
| 이해관계자와 관심사 | H: 세 도메인의 변동과 외부 원인을 한 화면에. 발주자: 발주자 메모 순서 준수 |
| 사전조건 | 새벽 배치가 한 번 이상 성공해 게시된 종합 리포트가 있다. H가 VODA에 로그인돼 있다 |
| 최소 보장 | 마지막 성공 리포트가 기준일과 함께 표시된다 |
| 성공 보장 | 시장지표 바, 헤드라인, 도메인 상태 3, 변동 목록이 2초 안에 표시된다 |
| 트리거 | H가 VODA 버튼 또는 단독 주소를 연다 |
| 패키지 | briefing |
| 포함(include) | — |
| 확장점(extension point) | 5. 근거 확인 → [[#UC-H2]] |
| 일반화 | — |

**기본 흐름**
1. 화면이 최신 게시 리포트를 조회한다(LLM 호출 없음).
2. 시장지표 바에 4종 지표(GPR, Brent, BDI, SCFI)의 최신값, 변화율, 기준일을 보여준다.
3. 헤드라인 1문장과 "상관관계 확인 · 인과관계 미확정" 배지를 보여준다. 헤드라인은 두 도메인 이상 또는 도메인과 외부 원인을 함께 말한다.
4. 도메인 상태 3카드(생산·판매·재고)에 신호등과 종합 관점 문장(강조 토큰 렌더)을 보여준다. 신호등은 2층 판정값에서 오고 문장은 3층이 새로 쓴 것이다.
5. 변동 목록을 국가별로 묶어 신호등 순으로 보여준다. 카드마다 변동, 원인 후보, 관련도, 연관 설명, 신규·상승 배지가 있다.
6. 원인 후보가 없는 변동은 "원인 미확인"으로 목록 끝에 둔다.
7. H가 도메인 상태 영역을 접거나 편다. 상태는 브라우저에 기억된다.

**확장**
- **1a. 게시된 리포트가 없다(첫 배치 전)**
  - 1a1. "리포트가 아직 생성되지 않았습니다"와 다음 배치 예정 시각을 보여준다.
- **1b. 최신 리포트가 강등본이다**
  - 1b1. 문장 자리에 템플릿 문장 또는 후보 목록만 보여주고 "생성 실패, 판정값만 표시" 안내를 붙인다.
- **4a. 비교 기간 데이터가 없다**
  - 4a1. 전월 대비로 표시하고 "계획·전년 데이터 미제공으로 전월 대비 기준"을 붙인다.
- **5a. 변동이 없다**
  - 5a1. "오늘 감지된 변동 없음"을 정상 상태로 보여준다.

#### UC-H2 변동의 외부 원인 후보와 근거를 확인한다

| 항목 | 내용 |
|---|---|
| 범위 | 종합 리포트 화면 |
| 수준 | 사용자 목표 |
| 주 액터 | H |
| 이해관계자와 관심사 | H: 왜 이 변동에 이 후보가 붙었나. 발주자: 근거 펼치기·링크 요구 |
| 사전조건 | [[#UC-H1]]이 표시돼 있고 변동 카드가 1건 이상 |
| 최소 보장 | 카드의 변동 사실과 후보 요약은 항상 보인다 |
| 성공 보장 | 후보 전부가 관련도 순으로 펼쳐지고 기사 3건 이상, 지표 원값, 각주 대응이 보인다 |
| 트리거 | H가 카드의 "근거 펼치기"를 누른다 |
| 패키지 | briefing |
| 포함(include) | — |
| 확장점(extension point) | 4. 기사 원문 → 새 창 |
| 일반화 | — |

**기본 흐름**
1. 카드가 변동(값, 기준 방식), 노출(CBU 비중), 관련도 높음 후보(사건 제목, 기사 수), 연관 설명 한 문단, 관련 법인 태그를 보여준다.
2. H가 근거 펼치기를 누른다.
3. 후보 전부를 관련도 순으로 펼친다. 사건은 제목과 기사(제목, 출처, 게시일, URL), 시장지표는 변화율과 원값, 타 도메인 변동은 값이다. 관련도 무관 후보도 접힌 채 남는다.
4. H가 기사 제목을 누르면 새 창으로 원문 URL을 연다. 화면은 외부 자원을 불러오지 않는다.
5. H가 연관 설명의 각주 번호를 누르면 해당 후보가 강조된다.

**확장**
- **1a. 관련도 높음 후보가 없다**
  - 1a1. "원인 후보 확인 안 됨"을 보여주고 신호등을 붙이지 않는다. 후보는 낮음·무관으로만 펼쳐진다.
- **1b. 법인 매핑이 없다**
  - 1b1. 태그를 "법인 미매핑"으로 보여준다.
- **1c. CBU/CKD 유도가 안 됐다**
  - 1c1. "노출 미확인"을 보여주고 신호등은 YELLOW 이하다.
- **3a. 라이선스 제한으로 기사 본문 비노출**
  - 3a1. 제목·출처·링크만 보여준다(미결).

### 2.3 관리

#### UC-A1 데이터 파일을 적재한다

| 항목 | 내용 |
|---|---|
| 범위 | 관리 화면 |
| 수준 | 사용자 목표 |
| 주 액터 | A (운영 개발자) |
| 이해관계자와 관심사 | A: 행수·결측·매칭률 확인. 발주자: 원본 보존 |
| 사전조건 | A가 관리 화면에 로그인. 소스별 스키마 버전이 등록돼 있다 |
| 최소 보장 | 원본 파일이 보존되고 실패 사유가 이력에 남는다 |
| 성공 보장 | L0·L1까지 적재되고 결과 수치가 이력에 남는다 |
| 트리거 | A가 소스를 고르고 파일을 올린다 |
| 패키지 | ingest |
| 포함(include) | [[#UC-S6]] 회귀 검사 |
| 확장점(extension point) | 5. 백필 모드 |
| 일반화 | — |

**기본 흐름**
1. A가 소스(완성차 생산, 완성차 판매재고, 뉴스, 블룸버그, Marklines, 크로스워크)를 고르고 파일을 올린다.
2. 시스템이 원본을 보존하고 스키마 버전을 판별한다.
3. 시스템이 검증 결과(컬럼 대조, 기준 기간, 행수, 결측, 빈 골격 행, 중복 의심)를 보여준다.
4. A가 적재를 확정한다. 같은 기준일자가 있으면 덮어쓰기임을 안내한다.
5. 시스템이 L0 저장, L1 표준화, 미매핑 수집, 회귀 검사([[#UC-S6]])를 돌리고 결과를 이력에 남긴다.
6. A가 필요하면 해당 기간 배치 재실행([[#UC-A4]])을 요청한다.

**확장**
- **2a. 스키마 버전을 판별할 수 없다**
  - 2a1. 어느 컬럼이 다른지 보여주고 적재를 막는다. 새 버전 등록은 개발 작업이다.
- **5a. 백필 모드**
  - 5a1. 결합 테이블까지만 채우고 LLM 세 역할(명명·연관·서술)을 생략한다.
- **5b. 회귀 검사 급변**
  - 5b1. 적재는 완료하되 배치 자동 실행을 막고 A에게 확인을 요구한다.

3. event를 갱신하고 명명 버전을 남긴다.

**확장**
- **2a. H-chat 실패·콘텐츠 필터·JSON 위반**
  - 2a1. 대표 기사 제목, 카테고리, 최대 impact로 대체하고 사유를 기록한다([[#UC-S7]]).
- **2b. 백필 모드**
  - 2b1. 호출을 생략한다.
