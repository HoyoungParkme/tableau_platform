# USECASE (Cockburn)

## 0. 이 문서의 형식과 용어

Cockburn 완전 서술형. 항목 ID는 `UC-{액터코드}{번호}`. 액터코드 H는 현업 사용자, A는 관리자(운영 개발자와 자사 DBA), S는 시스템(배치 스케줄러)이다. 사용자 목표 수준은 한 번의 이용으로 목표가 끝나는 것, 하위기능 수준은 사용자 목표 유스케이스가 포함(include)하는 내부 단계다. 확장은 `3a.` 형식이다.

리포트 4개의 이름은 아래로 고정한다(PRD 6.17). 액터코드 A(관리자)와 리포트 A는 다른 것이다.

| 이름 | 무엇 | 만드는 곳 | 원인을 찾는 곳 |
|:--|:--|:--|:--|
| A1 | 생산 리포트. 생산 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 생산 대시보드 데이터 안 |
| A2 | 재고 리포트. 재고 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 재고 대시보드 데이터 안 |
| A3 | 판매 리포트. 판매 대시보드에 붙는 AI 인사이트 | 브리핑 갈래 | 판매 대시보드 데이터 안 |
| C | 종합 리포트. 과업지시의 "인텔리전스 서비스 개요" 화면 | 이 문서의 시스템 | 뉴스·블룸버그(외부) + 세 도메인 교차 |

"A 리포트"는 A1~A3를 통칭한다. "A 판정"은 A 리포트가 만든 스냅샷 변동 판정값과 내부 분해 결과다. C는 A 리포트의 요약이 아니라 별개 인사이트다. A 리포트에서 C로 들어가는 화면 흐름은 없다.

근접도는 코드가 후보마다 세는 값 넷이다(PRD 6.14, [[TBL-PRD-002#R10]]). 변동 시점과의 날짜 차이, 기사 수, 출처 수, 국가가 어떻게 걸렸는지. 관련도 등급은 두지 않는다. 신호등 값은 red·yellow·none·notApplicable 넷이고 notApplicable의 화면 표기는 "판정 대상 아님"이다.

실측 제약 셋이 여러 유스케이스에 걸린다([[TBL-RFQ-002]] 4.2절).

| 제약 | 걸리는 유스케이스 |
|:--|:--|
| 완성차 데이터 형태가 둘(IF 원장, 피벗 리포트). 피벗 리포트의 총계 행은 상세 행과 범위가 다르다 | [[#UC-A1]] 형태 판별과 총계 행 분리, [[#UC-S4]] 기간 단위 |
| 생산에 목적지 국가가 없다 | [[#UC-H1]] 분해 한계, [[#UC-S5]] 신호등에서 제외 |
| 재고 원천이 없다 | [[#UC-H1]] 유도 지표, [[#UC-S4]] 단계별 흐름 차이 |

## 2. 사용자 목표 수준 유스케이스

### 2.1 A 리포트 (A1 생산 · A2 재고 · A3 판매)

#### UC-H1 A 리포트를 본다

| 항목 | 내용 |
|---|---|
| 범위 | 대시보드 3본에 붙는 A1·A2·A3 |
| 수준 | 사용자 목표 |
| 주 액터 | H |
| 이해관계자와 관심사 | H: 이 도메인에서 무엇이 변했고 어디가 만들었나. 발주자: 리포트마다 다른 인사이트 |
| 사전조건 | A 리포트 배치가 끝나 대시보드 스냅샷 판정이 있고, 게시된 A 리포트 사본이 있다 |
| 최소 보장 | 트래킹 지표의 변동 판정값이 표시된다 |
| 성공 보장 | 변동마다 내부 분해가 붙고, 못 만드는 지표가 명시되며, 외부요인 인용이 0건이다 |
| 트리거 | H가 VODA에서 생산·재고·판매 대시보드 중 하나를 열고 그 리포트의 서명 주소로 들어온다 |
| 패키지 | domain_report (브리핑 갈래) |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 리포트가 해당 도메인의 트래킹 지표와 변동 판정, 차트를 보여준다. 지표와 분해 차원은 실측에 근거하며 셋이 서로 다르다([[TBL-PRD-002#R1]]).

| 리포트 | 트래킹 지표 | 분해 차원 |
|:--|:--|:--|
| A1 생산 | 사업계획 대비 달성률, 완성차 비중, 수출 비중 | 생산법인, 공장지역, 세부지역, 차종그룹, 차급 |
| A2 재고 | 유통 체류(유도), 재고 회전, 현지재고 | 국가, 차종 |
| A3 판매 | 도매 대비 소매 격차(유통 체류율), 계획 대비 진도율, 전년 동월 대비 | 국가, 차종그룹, 대리점, 차급, 완성차·반조립 |

2. 변동마다 그 대시보드 데이터 안에서의 분해를 보여준다. 기여 상위 항목을 비율과 절대 대수로 함께 적는다. 분해 블록(법인별 달성률, 단계별 흐름, 국가별 체류, 차종 분해)은 이 시스템이 자기 데이터로 만든다(유저 결정 2026-10-01).
3. 못 만드는 지표를 화면에 적는다. A1은 목적지 국가가 없어 공장까지만 분해되고 파워트레인은 절반이 미분류라 뺀다. A2는 재고 원천이 없어 항해중·선적대기·법인·딜러를 구분하지 못하고 국가별 재고 시계열도 없다. A3는 국가와 차종이 함께 있는 데이터가 미주뿐이다.
4. 요약과 해설 문장은 브리핑 갈래가 쓴 것을 게시 사본에서 읽어 보여준다. 도메인 안의 사실만 말한다. 뉴스·시장지표를 인용하지 않는다. C 리포트로 가는 버튼이나 링크는 없다.
5. 사이드의 버전 목록에서 직전 리포트를 고르면 그 버전 지면이 열린다.
6. 내려받기를 누르면 보고 있는 버전 지면을 PDF로 받는다. 서버가 요청마다 만들고 남기지 않는다.

**확장**
- **1a. 트래킹 지표가 아직 현업 인터뷰로 확정되지 않았다**
  - 1a1. 위 표의 실측 후보를 임시로 쓰고 임시 지정임을 표시한다.
- **1b. 변동이 없는 날**
  - 1b1. "감지된 변동 없음"과 지표 현황만 보여준다. 리포트는 그대로 나간다.
- **1c. 주소가 맞지 않거나 그 리포트 제공이 꺼졌다**
  - 1c1. 리포트를 그리지 않고 안내만 낸다. 다른 리포트의 주소로도 열리지 않는다([[#UC-A4]]).
- **2a. 분해할 차원이 없다**
  - 2a1. 변동 판정만 보여주고 "분해 불가"를 표시한다.
- **3a. A2의 재고 원천이 들어왔다**
  - 3a1. 유도 지표를 실측값으로 교체하고 유도 표기를 내린다([[TBL-PRD-002#R9]]).
- **4a. 게시 사본이 없다**
  - 4a1. 판정값과 차트만 보여주고 "리포트 문장 미수신"을 표시한다.
  - 4a2. 내려받을 지면이 없어 내려받기를 막는다.

### 2.2 C 리포트 (종합, 인텔리전스 서비스 개요)

#### UC-H2 오늘의 C 리포트를 본다

| 항목 | 내용 |
|---|---|
| 범위 | C 리포트 화면 (인텔리전스 서비스 개요) |
| 수준 | 사용자 목표 |
| 주 액터 | H |
| 이해관계자와 관심사 | H: 세 도메인의 변동과 외부 원인을 한 화면에. 발주자: 발주자 메모 순서 준수 |
| 사전조건 | 새벽 배치가 한 번 이상 성공해 게시된 C 리포트가 있다. 관리자가 C 리포트 화면의 서명 주소를 VODA에 걸어 두었다([[#UC-A4]]) |
| 최소 보장 | 마지막 성공 리포트가 기준일과 함께 표시된다 |
| 성공 보장 | 시장지표 바, 헤드라인, 도메인 상태 3, 변동 목록이 2초 안에 표시된다. 같은 변동의 수치가 A 판정과 일치하고 문장은 A 리포트와 다르다 |
| 트리거 | H가 VODA에서 C 리포트 서명 주소를 연다. 추가 로그인 없음 |
| 패키지 | report |
| 포함(include) | — |
| 확장점(extension point) | 5. 근거 확인 → [[#UC-H3]] |
| 일반화 | — |

**기본 흐름**
1. 화면이 최신 게시 리포트를 한 번의 호출로 조회한다(LLM 호출 없음).
2. 시장지표 바에 4종 지표(GPR, Brent, BDI, SCFI)의 최신값, 변화율, 기준일을 보여준다. 완성차·뉴스·시장 각각의 데이터 최신일을 따로 적는다.
3. 헤드라인 1문장과 "상관관계 확인 · 인과관계 미확정" 배지를 보여준다.
4. 도메인 상태 3카드(생산·재고·판매)에 신호등과 종합 관점 문장을 보여준다. 신호등은 5단계 규칙이 정한 값이다. 판매와 재고 문장은 외부 원인에 비추어 서술되지만 생산 문장은 공장·차종 사실만 말한다. 생산 카드의 신호등은 "판정 대상 아님"이다.
5. 변동 목록을 국가별로 묶어 신호등 순으로 보여준다. 카드마다 변동, 내부 분해, 원인 후보의 제목과 근접도 값, 연관 설명, 신규·상승 배지가 있다. 등급 표시는 없다. 목록에 오르는 변동은 판매와 그 유도값이다.
6. 원인 후보가 없는 변동은 "원인 미확인"으로 목록 끝에 둔다.
7. H가 도메인 상태 영역을 접거나 편다. 상태는 브라우저에 기억된다.

**확장**
- **1a. 게시된 리포트가 없다(첫 배치 전)**
  - 1a1. "리포트가 아직 생성되지 않았습니다"와 다음 배치 예정 시각을 보여준다.
- **1b. 최신 리포트가 강등본이다**
  - 1b1. 문장 자리에 템플릿 문장을 보여주고 안내를 붙인다. 신호등과 후보 목록은 그대로 보인다.
- **1c. 오늘 배치가 실패했다**
  - 1c1. 마지막 성공 리포트를 보여주고 "오늘 배치 실패"와 마지막 성공일을 표시한다.
- **1d. 대시보드 판정을 받지 못했다**
  - 1d1. 보완 집계로 만든 리포트를 보여주고 "대시보드 판정 미수신"을 표시한다.
- **1e. 주소가 맞지 않거나 C 리포트 제공이 꺼졌다**
  - 1e1. 리포트를 그리지 않고 안내만 낸다. 자사 로그인 화면으로 보내지 않는다.
- **2a. 시장지표가 이월이다**
  - 2a1. 네 칸에 값과 이월 표시를 함께 보인다. 칸을 비우지 않는다.
- **4a. 비교 기준**
  - 4a1. 계획이 있으면 계획 대비, 없으면 전년 동월, 그것도 없으면 전월 대비로 표시하고 기준 방식을 붙인다.
- **5a. 변동이 없다**
  - 5a1. "오늘 감지된 변동 없음"을 정상 상태로 보여준다.
- **5b. 대시보드에 국가 시트가 없어 A 판정이 국가 단위가 아니다**
  - 5b1. 원장 보완 집계로 만든 국가 변동을 보여주고 카드에 "보완 집계"를 표시한다.

| 성공 보장 | 후보 전부가 시점 가까운 순으로 펼쳐지고 기사 3건 이상, 지표 원값, 각주 대응이 보인다 |
| 트리거 | H가 카드의 "근거 펼치기"를 누른다 |
| 패키지 | report |
| 포함(include) | — |
| 확장점(extension point) | 4. 기사 원문 → 새 창 |
| 일반화 | — |

**기본 흐름**
1. 카드가 변동(값, 기준 방식), 노출, 첫 후보의 제목과 근접도 값, 연관 설명 한 문단, 관련 법인 태그를 보여준다.
2. H가 근거 펼치기를 누른다.
3. 후보 전부를 시점 가까운 순으로 펼친다. 후보마다 근접도 값 넷이 그대로 적혀 있다. 사건은 제목과 기사(제목, 출처, 게시일, URL), 시장지표는 변화율과 원값, 타 도메인 변동은 값이다. 설명에 쓰이지 않은 후보도 접힌 채 남는다. 상한에 걸려 잘린 건수가 있으면 적는다.
4. H가 기사 제목을 누르면 새 창으로 원문 URL을 연다. 화면은 외부 자원을 불러오지 않는다.
5. H가 연관 설명의 각주 번호를 누르면 해당 후보가 강조된다.
6. 화면 어디에도 관련도 등급이 없다. 정렬 기준(시점 차이, 출처 수, 기사 수)이 화면에 적혀 있어 왜 이 순서인지 읽는 사람이 확인한다.

**확장**
- **1a. 사건 후보가 근거 기준에 못 미친다**
  - 1a1. 신호등을 붙이지 않고 "원인 후보 확인 안 됨"을 보여준다. 후보와 근접도 값은 그대로 펼쳐진다.
- **1b. 법인 매핑이 없다**
  - 1b1. 태그를 "법인 미매핑"으로 보여준다.
- **1c. 완성차 노출을 확인하지 못했다**
  - 1c1. "노출 미확인"을 보여주고 신호등은 yellow 이하다.
- **3a. 라이선스 제한으로 기사 본문 비노출**
  - 3a1. 제목·출처·링크만 보여준다(미결).

**기본 흐름**
1. A가 소스(완성차 생산, 완성차 판매, 뉴스, 블룸버그, Marklines, 크로스워크)를 고르고 파일을 올린다.
2. 시스템이 원본을 보존하고 형태를 판별한다. 첫 행이 바로 헤더이고 기준일자 컬럼이 있으면 형태 A(IF 원장), 병합 헤더가 2~3줄이고 기간 블록이 반복되면 형태 B(피벗 리포트)다.
3. 형태 A는 컬럼 대조, 기준일자 범위, 행수, 결측, 미래 골격 행을 검사해 보여준다.
4. 형태 B는 병합 헤더를 펼쳐 기간 구분과 지표 종류로 나눈 결과를 보여준다. 총계 행의 값, 차원 조합 수, 기간 블록 목록, 지표 종류 목록이 함께 나온다. 총계 행은 상세 행과 분리해 보관하며 상세 행 합과의 차이를 경고로 보인다. 파일 기준일을 A가 확인하거나 입력한다.
5. 계획이 두 종류이거나 도매가 두 기준이면 둘 다 들어왔다는 사실만 보인다. 정본은 여기서 고르지 않는다.
6. A가 적재를 확정한다. 형태 A는 기준일자 범위가, 형태 B는 파일 기준일이 겹치면 덮어쓰기임을 안내한다.
7. 시스템이 원본 저장, 표준화, 미매핑 수집, 회귀 검사([[#UC-S10]])를 돌리고 결과(형태, 기간 단위, 행수, 결측률, 매칭률)를 이력에 남긴다.
8. A가 필요하면 해당 기간 배치 재실행([[#UC-A3]])을 요청한다.

**확장**
- **2a. 두 형태 어느 쪽으로도 판별되지 않는다**
  - 2a1. 어느 대목이 다른지 보여주고 적재를 막는다. 새 형태 등록은 개발 작업이다.
- **4a. 총계 행과 상세 행 합의 차이가 크다**
  - 4a1. 경고로 남기고 적재는 진행한다. 검증식은 상세 행 합만 쓴다.
- **6a. 백필 모드**
  - 6a1. 후보·근접도·신호등까지 채우고 LLM 세 역할을 생략한다.
- **7a. 회귀 검사 급변**
  - 7a1. 수동으로 올린 파일이므로 적재는 마치되 배치 자동 실행을 막고 A에게 확인을 요구한다. 해제는 A가 한다.

**기본 흐름**
1. 적재: 배치 실행을 만들고 기준일을 정한다. 도착 파일이 있으면 [[#UC-A1]]과 같은 형태 판별·적재·표준화를 돌린다. 회귀 검사([[#UC-S10]]).
2. A 판정 읽기([[#UC-S2]]).
3. 사건 묶음([[#UC-S3]]). LLM 없음.
4. 결합([[#UC-S4]]). 변동 목록이 확정된다.
5. 원인 후보 검색, 근접도 계산, 신호등 판정([[#UC-S5]]). 도메인 상태 신호등도 여기서 정한다. LLM 없음. 여기서 화면에 나갈 판정이 전부 확정된다.

**확장**
- **1a. 회귀 검사 급변**
  - 1a1. 배치가 스스로 집어 온 파일이므로 배치를 멈추고 A에게 알린다.
- **1b. 적재 실패**
  - 1b1. 배치를 멈추고 이전 게시본을 유지한다.

#### UC-S4 결합해 변동 목록을 만든다

| 항목 | 내용 |

| 사전조건 | 표준화된 완성차 데이터, 사건, A 판정([[#UC-S2]])이 기준일까지 채워져 있다 |

| 트리거 | [[#UC-S1]] 4단계 |
| 패키지 | judgment |
| 포함(include) | — |
| 확장점(extension point) | — |

**기본 흐름**
1. 국가×기간 집계를 만든다. 판매는 선적·실 도매·도매(공식)·소매 네 계열, 생산은 계획과 실적, 완성차 비중이다. 기간 단위는 [[#UC-S2]]가 정한 것을 따른다. 총계 행은 집계에 넣지 않는다.
2. 단계별 흐름 차이를 계산한다([[TBL-PRD-002#R9]]). 선적 대비 도매 정본은 법인 구간, 도매 정본 대비 소매는 딜러 구간이며 화면 표기는 각각 법인 단계 체류와 유통 체류다. 국가마다 차이와 비율을 저장하고 음수도 정상 값으로 둔다.
3. 계획 값과 계획 정본 구분, 비교 값과 비교 방식을 행에 굳힌다. 계획이 있으면 계획 대비, 없으면 전년 동월, 그다음 전월이다. 정본은 설정 현재 버전에서 읽는다.
4. as-of 조인: 시장지표는 기준일 이전 최신값, Marklines는 최신 기준월.
5. A 판정값을 행에 붙인다. A 판정이 있는 지표는 그 판정을 쓰고, 없는 지표만 보완 집계 임계값(설정 현재 버전)으로 변동을 판정한다. 변동 판정은 3단계에서 굳은 비교 값과 비교 방식을 읽기만 한다.
6. 차종은 그룹 단위로 감지한다([[TBL-PRD-002#R13]], PRD 6.15). 세부 차종은 분해에만 쓴다.
7. 변동 목록을 만든다. 도메인, 국가, 지표, 값, 비교값, 기준 방식(계획·전년·전월), 출처(A 판정 / 보완 집계 / 유도), 내부 분해 결과.
8. 법인 태그: 매핑이 있으면 붙이고 없으면 "미매핑".
9. 사용한 설정 버전과 A 판정 스냅샷 ID를 저장한다.

**확장**
- **2a. 재고 원천이 들어왔다**
  - 2a1. 항해중·선적대기 비중을 실측으로 계산하고 유도값은 참고로 내린다. 행에 실측임을 기록한다([[TBL-PRD-002#R14]]).
- **4a. 시장지표 이월 한도 초과**
  - 4a1. 값은 이월값으로 두고 이월 표시를 세운다. 지표 바에 "기준일 지연"을 표시한다.
- **5a. 중복 적재 의심**
  - 5a1. 플래그를 세우고 도메인 상태에 "데이터 확인 필요"를 넣는다.
- **6a. 후속 모델 매핑 표가 들어왔다**
  - 6a1. 세부 차종을 이어 붙여 그 단위 감지를 다시 본다(PRD 6.15 재검토).

#### UC-S5 원인 후보를 찾고 근접도와 신호등을 정한다

| 항목 | 내용 |

| 성공 보장 | 변동마다 후보와 근접도 값이 저장되고 변동 신호등과 도메인 상태 신호등이 확정된다. LLM 호출 0건 |
| 트리거 | [[#UC-S1]] 5단계 |
| 패키지 | cause |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 국가 축이 있는 변동만 대상으로 삼는다. 생산 변동은 목적지 국가가 없어 제외된다.
2. 변동마다 같은 국가(해협 귀속 포함)의 열린 사건을 시간창 안에서 찾는다. 사건별 상위 기사 3건을 붙인다.
3. 같은 기간 시장지표 4종의 변화율이 설정 임계를 넘으면 후보에 넣는다.
4. 같은 국가의 다른 도메인 변동을 후보에 넣는다.
5. 후보마다 근접도 값 넷을 계산한다. 변동 시점과의 날짜 차이(사건은 마지막 관측일 기준), 기사 수, 출처 수, 국가 일치 방식.
6. 날짜 차이 오름차순, 같으면 출처 수 내림차순, 그다음 기사 수 내림차순, 셋이 모두 같으면 후보 식별자 사전순으로 정렬하고 상한(설정)까지 자른다. 이 순서가 화면 순서다. 넷째 기준은 동률을 가르는 장치라 화면 문구에 적지 않는다.
7. 변동 신호등을 정한다. 상한으로 자르기 전의 사건 후보 중(6에서 잘린 사건도 본다) 기사 수가 최소 이상, 출처 수가 최소 이상, 날짜 차이가 시간창 이하를 모두 채우는 것이 있는가. 있고 완성차 노출이 확인되면 red, 있고 노출이 미확인이면 yellow, 없으면 none(목록에는 남는다).
8. 도메인 상태 신호등을 정한다. 도메인 안 변동 신호등의 최댓값이다. 생산은 국가 축이 없어 notApplicable이다.
9. 변동 ID, 후보 유형, 후보 ID, 근접도 값 넷, 정렬 순서, 잘린 건수를 저장한다. 신호등과 그 근거(어느 후보의 어떤 값이 기준을 넘었나)와 설정 버전을 함께 저장한다.

**확장**
- **1a. 대상 변동이 판매와 유도값뿐이다**
  - 1a1. 정상이다. 생산이 국가 축을 얻기 전까지 이 상태가 유지된다.
- **2a. 시간창 안에 사건이 없다**
  - 2a1. 시장지표·타 도메인 후보만으로 진행한다. 사건 후보가 없으므로 신호등은 none이다.
- **6a. 후보가 상한을 넘는다**
  - 6a1. 잘린 건수를 기록하고 화면에 표시한다.
- **7a. 노출을 확인하지 못했다**
  - 7a1. "노출 미확인"으로 두고 red를 붙이지 않는다.

  - 2a1. 대표 기사 제목과 카테고리로 대체하고 사유를 기록한다([[#UC-S11]]).
- **2b. 백필 모드**
  - 2b1. 호출을 생략한다.
